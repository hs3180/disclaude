# Disclaude 0.6.27: codex app-server quota readings and named-channel download hints

Release preparation, 2026-11-10. This patch release packages the reviewed
runtime at main `23f4a8a6c`. Two merged fixes ship since 0.6.26: the codex
weekly-quota admission now recognizes the app-server transport's camelCase
rate-limit fields (#5734; #5740), and the file-download fallback command
pins the owning channel's appId in named deployments (#5738; #5743).
Release preparation changes only version metadata and documentation beyond
those reviewed changes.

## Changes

- Codex: `weeklyQuotaAdmission: enforce` gates on app-server readings too
  (#5734; #5740). The codex CLI reports the same per-window numbers over
  two transports with version-dependent field names: the exec JSONL
  `token_count` event carries snake_case `{used_percent, window_minutes,
  resets_at}`, while the app-server `account/rateLimits/updated` /
  `thread/tokenUsage/updated` notifications (codex 0.167) carry camelCase
  `{usedPercent, windowDurationMins, resetsAt}`. The rate-limit extractor
  previously matched only snake_case, so app-server readings were silently
  dropped and enforce admitted new sessions on "insufficient data" even
  with most of the weekly window spent. The extractor now accepts both
  spellings per field (snake_case first, camelCase fallback) and
  normalizes them into the same ledger window; primary/secondary/null
  windows, reset parsing, observe mode, and the exec path are unchanged,
  as is the existing policy that running turns, continued chats, and
  same-thread capacity-recovery retries are never terminated.
- Feishu: the file-download fallback hint targets the right app in
  named-channel deployments (#5738; #5743). When an agent cannot receive
  a file directly, the fallback hint command it receives is a
  `lark-cli ... --as bot` invocation that previously authenticated only
  from process-level environment credentials; a named-channel deployment
  has none, so the command was guaranteed to fail exactly when it was
  needed. The hint now resolves the owning channel's appId (channel
  client appId, then `LARKSUITE_CLI_APP_ID`, then the legacy
  `Config.FEISHU_APP_ID` — the same precedence as the real download
  path), pins it inline as `LARKSUITE_CLI_APP_ID=<appId>`, and names the
  tenant token the caller must export for that app. When no appId is
  resolvable the previous bare command is emitted unchanged, so
  single-app environment-credential deployments behave exactly as before.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.27"
disclaude --version
```

**Upgrade note.** No configuration migration is required. The quota fix
activates wherever `weeklyQuotaAdmission` is already configured; the
download-hint fix is automatic for named channels. Stop the running
service before upgrading and run `disclaude start` afterwards;
installation does not touch configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the
prior package remains installed for rollback.
