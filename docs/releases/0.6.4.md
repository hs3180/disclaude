# Disclaude 0.6.4: reliable turns, delivery and configuration

Release preparation, 2026-10-17. The stable `v0.6.4` tag and GitHub Release
have not been published. This document describes selected content and the
existing verification baseline; final package checks belong in release assets.

## Changes

### Turns and providers

- Keep active turns and native background Agents alive while work remains.
  Record one terminal outcome for a parent input even when its background child
  completes later; credit streamed/fallback delivery only to its owning turn.
- Preserve original input/run identity through iterator failure and service
  restart; report interrupted work without automatically replaying side effects.
- Let the Claude SDK own retries, compaction defaults and reported usage.
  Remove competing host query replay and the host retry-budget/audit layer.
- Send ordinary busy Claude input through the existing live input stream while
  running tools continue. Explicit `/stop` requests interruption; the chat
  accepts subsequent input. The closed interrupt-and-replace
  proposal in #5388 is excluded.
- Improve DSH UTF-8 Bash input, native compaction/overflow recovery, public task
  progress and selected-preset settings. Queue new LLM sessions at configured
  shared capacity; release Codex app-server slots with their connections.
- Bound Codex overload recovery before output or side effects, and improve stall
  attribution without treating quiet tools as abandoned work.

### Feishu delivery and command-line use

- Preserve canonical topic roots for replies, interactive cards and scheduled
  results. Deliver necessary public decision narration before tools while keeping
  internal thinking, raw tool payloads and child-agent frames private.
- Preserve final replies and in-flight REST requests. Improve question delivery,
  private-form delivery and expired-submission feedback; distinguish delivery
  outcomes from acceptance of a particular answer.
- Add local channel previews and single-layer JSON-file inputs, clearer command
  and recovery guidance, and safer attachment/topic handling. Reduce redundant
  group progress and duplicate author notifications.
- Preserve YAML strings on schedule writeback, report configuration/registration
  failures, and use the unified schedule concurrency policy.

### Configuration and optional plugins

- Bind named agents to named LLM settings. Require an explicit nonempty model
  for every named LLM, with selected-preset model, endpoint and credential
  isolation. The documented `CODEX_MODEL` override applies only after a valid
  default Codex model has been declared.
- Keep persistent secrets outside YAML. Resolve explicit external references,
  redact secret-file values even under opaque names, and project only the
  selected LLM's API/native mappings into its environment. Channel credentials
  remain with their host consumers; this is separate from filesystem/tool policy.
- Make diagnostics an explicit Project-local CLI-installed plugin, with safe
  discovery/removal across Claude, Codex, DSH and Pi. It is no longer installed
  silently with the default builtin skills.

### Jupyter, browser and installation

- Add explicit interrupt for an existing remote Jupyter kernel. HTTP acceptance
  is distinct from confirmed termination. Original-run `status`/`reconcile`
  preserves last-known facts through connection loss without replaying execution.
- Improve Jupyter credential discovery, structured diagnostics, source-hash
  errors and bounded traceback previews. The host remains Node-based; Python,
  Notebook content and kernel memory stay on the configured remote Jupyter.
- Distinguish CDP discovery, WebSocket attach and page-navigation failures with
  bounded safely redacted response summaries. Improve browser runtime ownership
  after PID reuse and authenticated VNC/noVNC defaults for headed containers.
- Use pinned pnpm for source worktrees and npm for prebuilt installations.
  Reuse installation download caches, clean owned temporary installs after safe
  completion and provide a read-only retention preview without automatic deletion.

## Install and configuration

After publication, install the prebuilt GitHub distribution with Node.js 20+, npm 10+ and Git:

```sh
npm install -g "github:hs3180/disclaude#v0.6.4"
disclaude --version
```

Use the [installation/rollback guide](git-install.md), [named-agent guide](../agent-configuration.md),
[secret-source guide](../configuration-secrets.md) and [channel credentials](../channel-credentials.md).
Configure the current schema explicitly; legacy-schema compatibility and an
automatic migration engine are not release requirements. Configuration is not
rewritten by installation. See [optional diagnostics](../skills.md#optional-diagnostics-plugin)
and the [remote Jupyter CLI](../jupyter-service.md) for those opt-in capabilities.

## Verified baseline and scope

Main source `193d83d82200ef78391908a61165f462151ef9dc` passed forced build/lint,
5,845 tests in 279 files, independent prebuilt installation and CLI lifecycle/data
preservation checks. Its authorized self-only Feishu acceptance used nine real
model inputs: eight Feishu inputs on Claude `glm-5.3` and one REST input on the
default Codex `gpt-6-luna`. Default stream/tool continuity, background completion,
topic narration, actual p2p interactive-card content, explicit stop/recovery and
REST final-only delivery have source-specific receipts.

The original daily service was restored with its original configuration/workspace;
actual help delivery and three healthy samples were verified. The
window observed no new shutdown interruptions, while retaining known historical
notification failures. This was temporary candidate acceptance, not a permanent
daily-service upgrade. Final stable-package hashes and installation/publication
results must identify their own source rather than relabel this baseline.

The maintainer closed #5354 as not planned: the `candidate-prefix-*` inventory
gap was waived, not fixed. Native session resume is future #5405; native model
private-input support (#5403), controlled answer-resolution ordering (#5404)
and queue/flood capacity work (#5399) also remain outside this release.
Browser diagnostics shipped, but the original #5352 incident remains unexplained
and that investigation is outside the milestone. These scope decisions do not
turn removed or deferred checks into passes. Historical RC records, failures
and their original source boundaries remain in [the RC record](0.6.4-rc.1.md).
