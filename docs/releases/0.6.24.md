# Disclaude 0.6.24: multi-app Feishu, build-time backend preinstall, mini-swe-agent, unified busy receipts

Release preparation, 2026-11-09. This patch release packages the reviewed
runtime at main `4ef795fa6`. Five merged changes ship since 0.6.23: named
multi-app Feishu channels with per-app defaults (#5254), Docker build-time
harness backend preinstallation (#5168), mini-swe-agent as an optional
agent provider (#5006), the unified busy-input receipt that gives Codex
interjection confirmations the same task context as Claude (#5713), and
the removal of the Pi implicit skills-manifest injection in favor of
native skill discovery (#5718). Release preparation changes only version
metadata and documentation beyond those reviewed changes.

## Changes

- Feishu: accept multiple named apps on a single instance (#5254;
  #5700). Channels declared with `type: feishu` under their own name
  each keep their own tenant token and lark-cli credentials, route
  chats under a stable `feishu:<name>:` identity, and can set a
  per-channel default agent preset (an explicit `/agent use` still
  wins). Text, cards, button callbacks, private-input flows, and image
  uploads use the owning channel's credentials; shared settings from
  the legacy `feishu` section (streamingCard, deduplication) still
  apply. With no declarations the legacy single-app configuration
  behaves exactly as before.
- Docker: preinstall harness backends at build time (#5168; #5710).
  The `DISCLAUDE_BACKENDS` build arg accepts `all` or a comma-separated
  subset of `claude`/`pi`/`codex`/`dsh` and drives a reproducible
  build-stage installer with pinned versions — CLI backends land on
  PATH and the Pi runtime packages in the production module-resolution
  path. Unknown names fail the build with an actionable error; no
  secrets or runtime configuration enter the image layers, and the
  container does not install anything at startup.
- Agents: add mini-swe-agent as an optional provider (#5006; #5711).
  Presets select the `miniswe` backend and reference a
  LiteLLM/OpenAI-compatible, provider-prefixed model; the `mini` CLI is
  detected with a clear unavailable error when missing, and Disclaude
  tasks map to local headless subprocess execution with isolated
  workspaces, per-run wall-clock timeouts, and credentials redacted
  from chat and logs. The default Codex path is unchanged.
- Chat: unify busy-input receipts across harnesses (#5713; #5714).
  The shared service-layer hint is now the only receipt source: the
  Codex native interjection confirmation carries the current task
  summary, elapsed time, and queue context instead of a fixed line,
  and harness-side standalone receipt building is removed so any
  backend that gains interjection support follows the same shape.
- Pi: remove the implicit skills-manifest injection (#5718; #5727).
  When the optional diagnostics plugin is installed, Pi sessions no
  longer receive a self-made "Disclaude skills:" manifest spliced into
  the system prompt. Disclaude built-in skills are registered through
  the shared native-skill-channel contract, and a skill source that
  cannot be delivered natively fails fast with an actionable
  diagnostic instead of silently degrading.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.24"
disclaude --version
```

**Upgrade note.** No configuration migration is required. Existing
single-app Feishu configurations keep working unchanged; multi-app and
`DISCLAUDE_BACKENDS` are opt-in additions. Docker deployments pick up
the new build arg only when they choose to use it. Stop the running
service before upgrading and run `disclaude start` afterwards;
installation does not touch configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the
prior package remains installed for rollback.
