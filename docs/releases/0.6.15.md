# Disclaude 0.6.15: Per-turn async capability, Jupyter runtime probing, automated group handoff

Release preparation, 2026-11-05. This patch release packages the reviewed
runtime at main `52366328e`, which adds seven scoped changes to the release
baseline: the per-turn async-question capability probe (#5665), the Node 22
docker entrypoint lark-auth fix (#5686), the de-hardcoded model/effort
collaboration rules (#5688), the unrecognized slash-command passthrough
regression lock (#5689), the automated discussion-group handoff (#5690), the
Jupyter kernel host/GPU runtime probe (#5691), and the report-deliverable
trigger for the research workflow skill (#5692). Release preparation changes
only version metadata and documentation beyond those scoped changes. The
final source commit, archive, checksums, and fresh installation results are
recorded in the release assets.

## Changes

- Async-question capability is now tracked per turn instead of per session
  (#5467; #5665). A new `asyncUserInputCapable` probe reflects exactly the
  conditions that reject async questions at runtime — once-mode sessions and
  superseded session generations — so the provider can announce the
  incapability in the prompt up-front, and an async question launched into
  such a turn is rejected as a structured "unsupported" error before any host
  wiring runs. The question degrades to plain text instead of surfacing a raw
  host rejection in the chat; blocking questions are unaffected.
- The Jupyter CLI gained a `runtime-probe` command that probes an existing
  kernel with fixed host-owned code and returns a hashed host id plus sorted
  unique GPU UUIDs under a stable `disclaude.jupyter-runtime.v1` schema
  (#5322; #5691). The probe never writes back to the Notebook and never
  runs agent-authored code; metadata that cannot be obtained is reported as
  an explicit `unknown` state rather than an empty list, so an agent can
  decide same-card exclusion (single-GPU mutual exclusion) without running
  `nvidia-smi` by hand on both sides.
- The start-discussion skill now performs the discussion-group handoff as
  one ordered chain (#5393; #5690): create the group with `--owner
  <triggering user>`, send the positioning first post (what this group
  covers, what stays in the old group, where the execution stream goes, the
  ledger rule), pin it, and reply with a migration card in the source
  thread — and only after that chain succeeds inject the initialization
  context. The bundled script stops at the first failed stage, is
  idempotent by key, uses argument arrays without a shell, and says so
  instead of being blindly re-run after a partial result.
- The docker entrypoint no longer silently skips lark-cli authentication on
  Node 22 (#5680; #5686). The FEISHU_AUTH extraction script is an IIFE with
  no top-level `return` (a SyntaxError on Node 22.23.4 that was previously
  swallowed by `2>/dev/null` plus a `none` fallback), the exit status is
  checked before treating the output as "not configured", and a real crash
  keeps its stderr and emits a WARNING instead of masquerading as a missing
  configuration. Real docker restarts previously left lark-cli-dependent
  skills silently broken in 0.6.11–0.6.14.
- Collaboration rules no longer hardcode a default model, a model ban, or a
  fixed reasoning effort (#5407; #5688). Model and effort selection follows
  the current user instructions and deployment configuration, historical
  acceptance results remain valid only for their original verification
  scope, and concrete model recommendations live only in the configuration
  example. This removes a real failure mode where repository rules rewrote a
  user-selected model into the repository default.
- The research-workflow skill now triggers on human-readable report
  deliverables (#5459; #5692): briefs, final reports, closing/experiment/
  analysis reports and feedback revisions on existing reports route to the
  research methodology, while simple factual Q&A, code comments, commit
  messages, plain data tables and other non-report writing stay out.
- The unrecognized slash-command passthrough contract is locked in by
  regression tests (#5401; #5689): an unregistered `/xxx` command — with
  arguments, multiline text, CJK content, quotes and mixed casing — is
  forwarded verbatim exactly once to the current agent across p2p, group
  mention and topic entry points, with or without a control handler, while
  registered-command argument errors, permission denials and execution
  failures stay out of the agent path. Runtime behavior was already
  correct; the tests prevent regressions.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.15"
disclaude --version
```

Existing 0.6.14 deployments keep their configuration, registry and
workspace data; stop the running service before upgrading and run
`disclaude start` afterwards. Installation does not touch configuration or
workspace data. Use the [installation/rollback guide](git-install.md) to
switch releases; the prior package remains installed for rollback.

Automated coverage does not replace real-environment acceptance: real
Feishu group handoff, real dual-GPU probe readings and real Docker restarts
with configured Feishu credentials remain outside the automated test scope
and should be verified in your own environment.
