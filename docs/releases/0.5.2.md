## Responsibility boundary

Agents and external skills choose uses, providers, endpoints, credential exchanges and credential lifecycle. Disclaude provides an independent handoff path and enforces its identity, destination and lifecycle boundaries. It does not classify ordinary content, interpret provider scopes, or add global logger/CLI/harness stderr filtering for this work.

#4973 tracks the generic delegation contract and its open audience/transport questions. #4974 is explicitly part of 0.5.2: move GitHub-specific skills out and provide a quick way to build external skills. Neither authorizes a general IAM or security-policy engine. Other original P1 work remains outside this release.

## User-facing changes

- Agents request private input through `disclaude channel request_private_input`, defining their workflow at task time. No `feishu.privateAction` preset is needed. Values arrive only through the selected consumer's stdin; the channel verifies actor/chat/source/card/nonce and returns fixed outcomes.
- The channel CLI uses the managed API address/token, accepts workflow JSON by file, argument or stdin, and emits one JSON result with an action ID. A successful request means the card was delivered, not that the workflow completed.
- Codex owns and reclaims its child processes, records bounded lifecycle/resource diagnostics and preserves input-to-delivery correlation. UNKNOWN recovery is bounded and does not replay user input automatically.
- Internal tool/status chatter stays out of ordinary chat. Explicit backend failures preserve the current agent instead of silently switching backends. Non-native compaction uses explicit configuration or available model metadata.
- GitHub authentication, issue-solver, pr-scanner and feedback skills are no longer bundled. The skill-creator prompt explains external skill authoring, including a single-skill GitHub App creation/authentication example. It ships no generator script.

## Migration and operation

Private workflows require service API authentication. Managed agents receive the API address and token. For a task, create a workflow JSON containing `title`, `description`, `command` and optional `args`, `cwd`, `env`, `timeoutMs`, then run:

```sh
disclaude channel request_private_input --chat <chat-id> --actor <initiator-open-id> --source <source-message-id> --workflow-file <workflow.json>
```

The workflow definition is not the private value. The user enters the value in the card; the agent-selected process handles its use. See [private workflows](../security/private-actions.md).

Existing user-installed skills, `.runtime-env`, schedules and workspace files are not deleted or automatically migrated. Move provider skills into a separately maintained external project, update any scheduled paths explicitly, and verify discovery in a fresh turn. Shared `.runtime-env` remains agent-managed workspace state; changes do not update environments of already-running processes.

The validated upgrade baseline is the pinned 0.5.1 Git distribution. Keep the prior distribution SHA and a workspace/config backup for rollback. Install the reviewed 0.5.2 distribution only after release approval; `github:hs3180/disclaude#v0.5.2` is a post-publication command, not an available tag promised by this preparation document.

## Limits

The channel is not an OS sandbox or global output sanitizer. Once a workflow receives a value, its subsequent use and persistence belong to the agent. API authentication is the trusted service-agent boundary, not a complete per-task delegation system (#4973). A form expires after five minutes and is one-use; revocation does not undo a consumer that already received input.

Private Feishu delivery is validated with callback/consumer fixtures; no live private card is claimed unless separately recorded. Oversized single model inputs can still fail before compaction. Docker work tracked for 0.5.1 is not claimed complete by this release.
