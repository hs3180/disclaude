# disclaude 0.5.2 发布目标

状态：用户于 2026-09-11 确认交付范围，仅包含下列 13 个 P0 issues。版本号和发布日期按后续实现与发布验收确定。

GitHub 跟踪：[0.5.2 milestone](https://github.com/hs3180/disclaude/milestone/16)。

## 版本定位

**让现有多 harness 服务能够长期稳定运行，失败可恢复、问题可追踪、敏感信息不泄露，用户只看到必要的交付和提示。**

0.5.0 已交付多后端接入、预设切换和可控调度；0.5.1 完成统一服务入口与 GitHub 安装链路。本版仅补齐下列运行与安全缺口。

交付范围锁定为下列 13 项。关闭或合并 PR、发布追溯表中的列项，都不能代替具体场景的验收证据。

## P0：必须满足的发布目标

### 1. 长期运行有界，失败后能够继续工作

| Issue | 交付目标 | 验收重点 |
|---|---|---|
| [#4916](https://github.com/hs3180/disclaude/issues/4916) | 回收 Codex app-server 所属工具子进程 | 明确 turn/session/provider 的所有权与回收时机；连续至少 100 次工具回合后，活跃进程与资源占用回到基线附近或受明确上限约束；取消、异常退出和释放不留孤儿进程 |
| [#4770](https://github.com/hs3180/disclaude/issues/4770) | 未知错误按有界策略恢复，暂停时给出可操作提示 | 首次 UNKNOWN 不直接归为永久错误；配置/权限等明确永久错误不重试；已发生工具副作用或提交状态未知时，不盲目重放；日志和用户提示能通过诊断 ID 关联 |
| [#4883](https://github.com/hs3180/disclaude/issues/4883) | 补齐非 Claude 模型压缩的行为边界 | 显式阈值、API 元数据、元数据缺失、关闭压缩及原生 Claude 模型分别验证；阈值跨越后保留关键上下文并继续；超大单次输入有明确错误/恢复行为，不承诺任意长度输入可成功 |
| [#4898](https://github.com/hs3180/disclaude/issues/4898) | 后端选择失败明确报错 | 审计启动、factory、命令切换和恢复路径；未知/不可用/不兼容选择不得静默换 harness；合法默认配置与错误后的 fallback 分开验证，失败切换保持旧会话 |

### 2. 凭据只进入明确允许的路径

沿用 [#4895](https://github.com/hs3180/disclaude/issues/4895) 已记录的轻量安全 P0 计划：由 agent／技能决定敏感性、鉴权用途和业务规则；disclaude 提供私密传递、凭据分发和显式输出保护，并阻止明确的重放、跨会话使用及进程控制注入。不增加通用 Secret Broker、Vault 或完整 RBAC 系统。

| Issue | 交付目标 | 验收重点 |
|---|---|---|
| [#4919](https://github.com/hs3180/disclaude/issues/4919) | 所有环境保护 harness 显式声明的敏感值 | 不按字段名或 token 样式猜测敏感性；嵌套错误、格式化日志和跨块 stderr 保护声明值；声明按使用生命周期释放；循环引用安全、不修改原对象，保留非敏感诊断 |
| [#4918](https://github.com/hs3180/disclaude/issues/4918) | 明确共享 runtime-env 的所有权 | 文件内容、凭据刷新和清理由 agent 维护；公共上下文说明跨 session／agent 共享、并发修改及环境快照语义；保留已合并的安全文件原语，不增加 host 键名或有效期策略 |
| [#4890](https://github.com/hs3180/disclaude/issues/4890) | 飞书卡片中的敏感输入仅交给指定服务端处理器 | 至少一个明确允许的真实操作闭环；绑定发起人/chat/原始动作/nonce/TTL，单次消费；拒绝过期、重放和跨会话提交；原始值不进入 agent、历史、工具输出和 runtime-env |
| [#4915](https://github.com/hs3180/disclaude/issues/4915) | 能读取仓库原生 Secret Scanning Alerts | 以既定只读权限成功读取真实告警状态；403 不能作为“无告警”。权限配置是外部依赖，规划本身不执行授权变更 |
| [#4895](https://github.com/hs3180/disclaude/issues/4895) | 汇总威胁模型和整改结果 | 覆盖已列出的攻击面；每项有证据、修复建议及处置去向；上述 P0 不以“已有计划”视为完成 |

## 范围约束

本版只交付上述 13 项 P0，不设 P1 可选交付包。原建议稿的 Skills Registry、reaction/欢迎/帮助、harness 契约清理、blocking 移除、全仓质量扫描、频控专项验收，以及插件化、新渠道、研究工作流等其他需求均留待后续规划。

实现中发现的问题，仅当直接阻断上述目标或其必要回归时纳入本版；不得通过安全总项、调试信息审计或发布回归扩展为无边界重构。新增独立功能需另行确定版本归属。

## 与 0.5.1 的边界

[#4924](https://github.com/hs3180/disclaude/issues/4924) 继续属于 0.5.1：源代码重构、统一 CLI 和正式 tag 安装矩阵已有证据，Docker 全运行验收仍缺。不能通过改挂 0.5.2 来宣称 0.5.1 已完成发布。

0.5.2 可从已合并源码继续开发。发布前明确 0.5.1 的最终处置与实际升级基线；若支持从 0.5.0 和 0.5.1 升级，两条路径都应验收。旧版本的已通过矩阵不替代新候选的安装和部署测试。

## 实施顺序

1. 确认现行基线与复现：进程增长、UNKNOWN 错误、压缩场景、工具/status 泄露及凭据路径。沿用现有实现，避免重做已经关闭的 28 项。
2. 先处理 #4919/#4918，为诊断与私密输入提供可靠基础；同步确认 #4915 的外部权限依赖。
3. 完成进程所有权/回收、有界恢复和交付过滤；#4746 的关联信息接入统一脱敏链路。
4. 完成 #4890 的单一允许动作闭环，复核 #4898 和 #4883；逐项汇总 #4895 的整改证据。
5. 汇总 13 项 P0 的验收证据，冻结实现，构建发行候选并进行升级/回退验证。

## 发布门槛

- P0 每项有对应源码提交、精确测试场景、实际结果和剩余限制；不能只列文件名、测试数量或“已合并”。
- lint、type-check、build、相关单元/集成回归通过。Claude、Codex exec/app-server、Pi、DSH 的适用路径分别验证；不支持的能力明确拒绝。
- 连续工具回合、停止/取消/异常退出/忘记会话/provider 销毁覆盖子进程回收；用户会话无串扰、重复执行或静默丢结果。
- 真实服务链路覆盖普通聊天、线程/parent 回复、流式收尾及失败降级；涉及私聊、话题群、卡片路径的改动必须补相应场景。
- 敏感输入、重放/跨会话拒绝、共享环境边界提示和显式声明值保护有端到端证据；Secret Scanning Alerts 成功读取，实际告警按结果处置。
- 使用候选对应的预构建 Git 发行提交完成远程安装，覆盖 Linux/macOS、Node 20/22、npm 10/11；正式 tag 与已验收源码指纹对应。Release 资产来自同一候选。
- CLI start/status/stop/restart、配置/workspace/会话/定时任务保留、服务升级和回退通过。对本版承诺支持的 Docker 部署提供真实容器验收。
- 更新发布说明和所有已变更公开字段的迁移指引；日期由验收决定。创建公开标签、发布 Release 和部署仍按实际发布指令执行。
