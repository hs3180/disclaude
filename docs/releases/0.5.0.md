# disclaude 0.5.0 发布目标

状态：目标已确定，尚未发布；验收尚未完成。

确定日期：2026-09-08。依据：当日 48 个 open issues 的用户影响、架构覆盖面和依赖关系，父子 Issue 按一项能力归并。历史 milestone 名称不作为范围依据。

## 版本定位

**多后端 Agent 的统一使用与可控自动化。**

让用户能在会话中选择和控制不同 Agent 后端，并让后台任务按需调用模型、控制上下文增长、可靠交付结果。三项核心更新为：多后端选择与切换、运行中交互控制、低成本可靠调度。

本文件是发布范围与验收标准的依据；GitHub milestone 和跟踪 Issue 用于执行追踪。这里的 P0/P1 是发布优先级，不改变各 Issue 的缺陷严重程度。版本号与发布日期在正式发布时更新，不提前将目标标成已实现。

开发执行入口：[LOOP.md](0.5.0/LOOP.md)；工作包、依赖与验收：[SPECS.md](0.5.0/SPECS.md)。九个工作包覆盖 37 个核心/配套 Issue；规格本身不启动后台任务。

## P0：三项核心目标

### 1. 多后端统一选择与切换

- 支持多份命名 backend/model 预设，默认项规则明确，兼容现有单一 agent 配置。
- 内置命令可查看当前生效配置、列出选择项并切换后端或模型；具体命令语法由实现确定。
- 完成 DeepSeek harness 的配置、会话生命周期、事件映射、工具调用、飞书交付与端到端测试。
- 对 Claude、Codex、pi 和新增 DeepSeek 明确能力矩阵；不支持的切换方式提前说明，不承诺后端之间原生上下文无损迁移。

关联：[#4772](https://github.com/hs3180/disclaude/issues/4772)、[#4724](https://github.com/hs3180/disclaude/issues/4724)、[#4723](https://github.com/hs3180/disclaude/issues/4723)、[#4740](https://github.com/hs3180/disclaude/issues/4740)（子任务 #4741–#4745）、[#4383](https://github.com/hs3180/disclaude/issues/4383)。

验收：预设解析与旧配置兼容通过；有效切换返回实际 backend/model；失败不破坏当前会话；正式支持的每个后端通过对话、工具、异常和最终交付测试。pi 按现有实现补验收，不重复建设已完成部分。

### 2. 运行中的 Agent 可干预、过程与结果可见

- Codex 明确区分停止当前回合、追加排队和立即追问/steer，并向用户反馈实际状态。
- 打断后可基于已有上下文继续交流；在工具执行、重试和会话恢复边界保持一致语义。
- 完成飞书流式卡片状态机、每会话节流与收尾；过滤不必要的工具过程消息。
- 流式失败降级为普通消息；每个回合有可见的成功、失败或取消结果。

关联：[#4825](https://github.com/hs3180/disclaude/issues/4825)、[#4208](https://github.com/hs3180/disclaude/issues/4208)、[#4399](https://github.com/hs3180/disclaude/issues/4399)、[#4398](https://github.com/hs3180/disclaude/issues/4398)、[#4774](https://github.com/hs3180/disclaude/issues/4774)、[#4747](https://github.com/hs3180/disclaude/issues/4747)、[#4770](https://github.com/hs3180/disclaude/issues/4770)。

验收：停止、排队、steer 分别有回归证据；取消后不再派发新的工具调用，记录取消确认与子进程退出耗时及不可中止操作的边界；卡片更新、限流、并发、失败降级均不丢最终结果。已有卡片基础设施按剩余缺口验收。

### 3. 低成本且可靠的后台调度

- schedule 支持脚本模式，纯轮询直接执行脚本，仅有变化时经统一 push 入口唤醒 Agent。
- 明确新会话、历史快照和完全清空上下文的区别，修复默认复用持久会话引起的增长问题，提供旧配置迁移说明。
- 历史在实例首条消息按预算注入；迭代账本有保留上限和归档方法，旧状态可追溯。
- 按消息/执行标识结算并发回合，修复 FIFO 错配；定时任务的模型配置无效时明确提示。

关联：[#4798](https://github.com/hs3180/disclaude/issues/4798)、[#4812](https://github.com/hs3180/disclaude/issues/4812)、[#4810](https://github.com/hs3180/disclaude/issues/4810)、[#4795](https://github.com/hs3180/disclaude/issues/4795)、[#4808](https://github.com/hs3180/disclaude/issues/4808)、[#4773](https://github.com/hs3180/disclaude/issues/4773)。

验收：无变化脚本轮询产生零 LLM 调用；有变化时能唤醒并交付；超时、失败计数、冷却和阻塞语义仍有效；多轮执行的历史注入与活跃账本维持配置上限；并发完成、取消和超时准确归属任务，不误报其他任务失败。

## 不纳入本版承诺

- 完整 Jupyter/Notebook 交互界面、一日或一周无人值守任务、大型知识图谱、新聊天平台。
- Chromium 有头环境增强 #4800、通用 daemon skill #4796 等独立能力，不作为三项核心目标的前置。
- 不因历史 milestone 下已有研究类关闭 Issue，就认定新的发布目标已完成；历史记录保留供追溯。

## 发布门槛与执行顺序

1. 先按各目标确定验收场景、能力矩阵、配置兼容与切换/取消边界，核对已有实现。
2. 完成命名预设与切换、DeepSeek 接入；推进运行中控制与卡片收尾；完成脚本调度和上下文治理。
3. RC 阶段逐项记录测试命令、结果、日志或产物及已知限制，至少覆盖：每个正式后端的对话/工具/异常/交付、切换失败、运行中停止与追问、流式降级、空轮询、有变化唤醒、并发结算、重启和多实例端口。
4. 必需 CI 通过（构建、类型、lint、单测、现有覆盖率门槛），相关集成测试通过；Docker/macOS launchd 安装、升级与回退演练通过，文档命令与实际入口一致。
5. 会话或项目串扰、停止失效、静默丢失最终结果、并发任务错配等发布阻塞问题为零；P0 全部有验收证据，配套项的延期如有则显式记录。
6. 验收完成后才更新发布版本、整理实际 Changelog 并发布。根包目前 private 与 npm publish workflow 的发布方式矛盾须在发布准备中解决，不能直接触发现有工作流当作验证。

发布日期不预设；按上述门槛决定。P1 未完成项单独列出，不伪装为已交付功能。
