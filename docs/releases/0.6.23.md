# Disclaude 0.6.23: CI runner pin for the Jupyter patch workflow

Release preparation, 2026-11-09. This patch release packages the reviewed
runtime at main `6ae6a50cb`. The single merged change since 0.6.22 pins the GitHub Actions runner for the `datalayer-package`
(Jupyter patch CLI) workflow to `ubuntu-24.04`: `ubuntu-latest` has rolled
to 26.04, whose `actions/setup-python` toolcache no longer provides
Python 3.9, which randomly turned the Node18/Py3.9 compatibility leg red
(and, via fast-fail, cancelled the Node24/Py3.13 leg) on main pushes and
PRs that trigger the workflow. Pinning the runner keeps the existing
support matrix intact. This is a continuous-integration-only change: the
packaged runtime is unchanged from 0.6.22 (same build fingerprint), and
nothing changes for installed deployments. Release preparation changes
only version metadata and documentation beyond that scoped change. The
final source commit, archive, checksums, and fresh installation results
are recorded in the release assets.

## Changes

- CI: pin the `datalayer-package` workflow runner to `ubuntu-24.04`
  (#5735). On `ubuntu-latest` after its roll to 26.04, the
  Node18/Python 3.9 matrix leg failed at `actions/setup-python` ("The
  version '3.9' … was not found for Ubuntu 26.04") and fast-fail
  cancelled the remaining leg, polluting merge signals on commits whose
  content was unrelated to the failure. The pinned runner restores both
  legs to green while preserving the tested Node/Python support matrix.
  Repository CI configuration only — no product code changes.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.23"
disclaude --version
```

**Upgrade note.** No configuration migration is required; 0.6.23 is a
drop-in replacement for 0.6.22 — the packaged runtime is unchanged and
the only difference is repository CI configuration. Existing deployments
keep their configuration, registry, and workspace data; stop the running
service before upgrading and run `disclaude start` afterwards.
Installation does not touch configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the
prior package remains installed for rollback.
