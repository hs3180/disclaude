# Disclaude 0.6.6: personal WeChat and channel coexistence

Release preparation, 2026-10-21. This patch release packages the reviewed
runtime at main `d7ed69eee5e077b6b201cae7473bcc4d4c697782`. Release preparation
changes only version metadata and documentation; it does not add fixes for
unrelated open issues. The final source commit, archive, checksums, and fresh
installation results are recorded in the release assets.

## Changes

- Connect a personal WeChat bot using Tencent iLink QR login, with persistent
  credentials, sync cursor, accepted-message IDs, and per-peer reply contexts.
- Download/decrypt incoming images and files into the common Agent attachment
  path; upload encrypted images, ordinary files, and native MP4 videos.
- Forward the existing public progress and decision summaries before the final
  reply through ordinary WeChat text messages.
- Enable Feishu, REST, and WeChat in one service. Route known conversations to
  their owner, reject unknown/ambiguous targets, and retain healthy channels
  when another channel fails to start.
- Register accounts dynamically from zero-account startup. Use stable system
  IDs and account-scoped histories/state; add, enable, disable, reauthenticate,
  or remove registrations without editing an account list or restarting the
  whole service.
- Use the running installation's complete channel CLI prefix. Keep CLI
  diagnostics on stderr, structured results on stdout, and host file-log
  permissions outside the CLI path.
- Run Docker service and Chromium container acceptance only when manually
  requested; regular core CI remains enabled.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.6"
disclaude --version
disclaude wechat login
disclaude wechat status --check
```

Enable `channels.wechat` in the existing named-agent configuration. See the
[WeChat guide](../wechat-channel.md) for the registry directory, current CLI,
coexistence configuration, and recovery behavior. Installation does not
rewrite configuration or workspace data. Keep the prior package and use the
[installation/rollback guide](git-install.md) for an existing deployment.

This is the personal iLink bot integration, not WeCom, Official Accounts, or
WeChat groups. Native video output supports MP4; input video/voice decoding,
WeChat cards/buttons, and streaming edits are outside the supported scope.
The local limits remain 4000 UTF-8 bytes per text part and 20 MiB per file.
An accepted API request is not a phone read receipt; ambiguous or partially
sent operations are not blindly retried.
