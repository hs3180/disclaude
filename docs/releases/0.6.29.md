# Disclaude 0.6.29: dual-app mention routing, context recovery guidance, and WeChat upload watchdog fix

Release preparation, 2026-11-18. This patch release packages the reviewed
runtime at main `42da46aa0`. Four merged fixes ship since 0.6.28: the
self-sent echo registry is keyed by routed message id so a second named
Feishu app no longer drops legitimate @mentions (#5737; #5744), agents are
guided to recover missing context through `disclaude history query` before
guessing or re-asking (#5746; #5748), the WeChat CDN upload watchdog no
longer misjudges slow sustained transfers as stalls (#5751; #5753), and a
token-boundary assertion keeps the miniswe runner unit test from flaking on
random path suffixes (#5749). Release preparation changes only version
metadata and documentation beyond those reviewed changes.

## Changes

- Key the self-sent echo registry by routed message id
  (`feishu:<channel>:<id>`) instead of the bare Feishu message id
  (#5737; #5744). Previously the registry was process-global, so when one
  instance hosted two named Feishu apps, a legitimate @mention arriving in
  app B with the same message id as an app A self-sent echo was silently
  dropped as an echo. Echoes are now filtered only within the owning app's
  channel; single-app deployments resolve bit-identically (locked by
  regression coverage), and `POST /api/self-sent/:messageId` accepts an
  optional `?channel=<name>` parameter for scoped registration while
  staying compatible with existing callers.
- Add stable guidance that routes missing-context requests through
  `disclaude history query` (#5746; #5748). When a request leans on
  earlier context the current session cannot see (for example "revise that
  earlier article") or is the first message of a fresh session after a
  preset switch, the agent is instructed to run
  `disclaude history query --chat <Chat ID> --days 2 --limit 50` first,
  then ask one short clarifying question listing candidate referents if
  the answer is still ambiguous, and to say plainly which context is
  missing when the query fails — never to invent context or make the user
  re-send material already in history. The same ordering rule is captured
  in the history skill documentation and the README.
- Chunk WeChat CDN upload body writes and re-anchor the stall watchdog to
  true link silence (#5751; #5753). Bodies are handed to the transport in
  backpressure-aware 64 KiB chunks, so a sustained but slow TLS transfer
  (observed in production with 14.6 MB and 5 MB MP4 deliveries) counts as
  write activity and is no longer killed by the 15-second stall budget;
  the total deadline budget is preserved. Stall, connect-budget,
  deadline, cancel, and error paths now settle exactly once, clear all
  timers and listeners, and destroy the request, so a reported failure
  never leaves the POST transmitting in the background (eliminating the
  duplicate-upload retry risk). `writtenBytes` progresses per chunk and a
  new `acknowledged` mark separates local handoff from the first CDN-side
  response. Regression tests replay real loopback TLS with per-chunk
  backpressure (8 MiB over 19.4 s) and a true mid-write stall.
- Assert `-m` omission on argv token boundaries in the miniswe runner
  test (#5749). The captured argv line embeds mkdtemp paths whose random
  suffix can start with `m` right after the prefix dash, which made a bare
  substring check on `-m` flake about 1.5% of runs and intermittently
  reddened the main Unit Tests check. The runner always emits `-m` as a
  standalone token, so the token-boundary match keeps the same detection
  power while ignoring path contents. Test-only; product behavior is
  unchanged.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.29"
disclaude --version
```

**Upgrade note.** No configuration migration is required. All four fixes
are automatic: mention routing keys are internal, the context-recovery
guidance and history skill documentation are additive, and the upload
watchdog and test assertion changes need no configuration. Stop the
running service before upgrading and run `disclaude start` afterwards;
installation does not touch configuration, credentials, or workspace data.
Use the [installation/rollback guide](git-install.md) to switch releases;
the prior package remains installed for rollback.
