# Disclaude 0.6.9: browser runtime ownership and 404 recovery guidance

Release preparation, 2026-11-04. This patch release packages the reviewed
runtime at main `b91945367095`, which carries two browser-reliability fixes
beyond the 0.6.8 source: runtime ownership that survives `service.lock`
inode drift (#5474; #5661) and stage-matched recovery guidance for HTTP 404
failures (#5352; #5659). Release preparation changes only version metadata
and documentation beyond main.

Generated with the hardened release pipeline introduced in 0.6.8 (#5517,
#5522): stale build artifacts are pruned, the runtime is rebuilt from source
with `tsc --build --force`, the build asserts the source tree did not
change, and `release-source.json` records build provenance.

## Changes

- **Browser runtime ownership survives lock inode drift**: when
  `service.lock` is re-created at the same path (for example by a temporary
  directory cleanup) while the owner service is still alive, ownership is no
  longer revoked for the live runtime. The ownership proof matches the lock
  inode recorded in the runtime manifest and falls back to PID/lstart
  liveness checks when the inode drifted or was never recorded;
  `--reload` atomically heals the manifest evidence (pinning it to PID/lstart
  so a fresh inode cannot reintroduce the kill) and emits
  `browser-owner-evidence-refreshed` instead of aborting with "owner is not
  live"; the takeover gate is drift-aware — a live owner is never preempted,
  while a truly dead owner, including PID reuse, can still be taken over
  (#5474; #5661).
- **HTTP 404 diagnostics name their recovery path**: browser HTTP failures
  now carry a remedy matched to the failing stage through the existing
  `browserDiagnostic` record — `http-discovery` points at checking or fixing
  the endpoint (or restarting Chromium), `websocket-attach` explains that a
  stale CDP identity is refreshed by re-running discovery or `--reload`
  without restarting the service, and `page-navigation` points at the target
  URL. Remedies attach only for status ≥ 400 with a known stage; unknown
  stages and upstream exits stay unannotated (#5352; #5659).

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.9"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards
with `disclaude start`. The installation does not modify configuration or
workspace data. Existing 0.6.8 deployments keep their configuration,
browser runtime manifests, and workspace data; use the [installation/rollback
guide](git-install.md) to switch releases.
