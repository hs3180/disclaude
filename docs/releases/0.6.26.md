# Disclaude 0.6.26: Feishu agent-config card and per-run schedule harness

Release preparation, 2026-11-09. This patch release packages the reviewed
runtime at main `00123fd227`. Two merged changes ship since 0.6.25: the
native Feishu card for configuring the chat's agent
harness/model/thinking (#4914; #5707) and the per-run `harness` override
for prompt schedules (#5731; #5732). Release preparation changes only
version metadata and documentation beyond those reviewed changes.

## Changes

- Feishu: configure the chat agent with a native interactive card
  (#4914; #5707). Authorized users run `/agent config`; the card shows
  the current named preset (a legacy `agent:` configuration reads as "no
  named preset") and walks harness → model → thinking through constrained
  `select_static` menus populated only from configured presets — no
  free-text model IDs, single-option steps auto-skip, and a preset
  disambiguation step appears when the same combination maps to several
  named presets. Nothing changes until the explicit confirm step, which
  reuses the same preset catalog and `switchAgentPreset` service as the
  text commands; the switch starts a fresh native session (context does
  not migrate across presets) and survives service restarts, identical
  to `/agent use`. Cards bind to the requesting actor, chat, and message,
  re-check command authorization (`isCommandAllowed`) on every callback,
  expire after 10 minutes, serialize redraws per card, and treat
  duplicate applies or post-completion replays as idempotent no-ops.
  Channels without a card hook get the existing
  `/agent list` / `/agent use <name>` guidance, and preset queries expose
  an optional `reasoningEffort` so an unset thinking tier displays as
  "default" instead of a fabricated tier.
- Schedules: borrow an agent runtime for a single prompt execution
  (#5731; #5732). Schedule frontmatter accepts an optional `harness`
  naming a configured `agents:` preset. The borrowed runtime is used only
  for that execution's isolated `freshSession` — chat-level bindings and
  the global default are untouched. `model`, if set, is resolved and
  validated by the borrowed runtime's own rules (not the chat's). Unknown
  names, models invalid for that backend, missing credentials, or an
  unavailable backend fail that tick with an explicit, countable error —
  never a silent fallback to the chat binding or default. `harness` on a
  `command` schedule is rejected at parse time; the field is preserved by
  hot-reload rewrites and takes effect from the next tick without
  catching up missed runs.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.26"
disclaude --version
```

**Upgrade note.** No configuration migration is required. `/agent config`
appears wherever the Feishu channel is enabled; the schedule `harness`
field is opt-in per task. Stop the running service before upgrading and
run `disclaude start` afterwards; installation does not touch
configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the
prior package remains installed for rollback.
