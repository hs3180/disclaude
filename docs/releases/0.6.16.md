# Disclaude 0.6.16: Layered non-technical welcome, Jupyter tools schema completion

Release preparation, 2026-11-06. This patch release packages the reviewed
runtime at main `866fe94d5`, which adds two scoped changes to the release
baseline: the non-technical, capability-trimmed automatic welcome message
(#5704) and the Jupyter `tools` schema completion with unified JSON input
and documented Notebook contracts (#5706). Release preparation changes only
version metadata and documentation beyond those scoped changes. The final
source commit, archive, checksums, and fresh installation results are
recorded in the release assets.

## Changes

- The automatic welcome is now written for non-technical first-time users
  and trimmed to what each channel can render (#5475; #5704). A single
  task-oriented template, `buildWelcomeMessage(channel)`, backs both the
  WeChat and the Feishu automatic welcome: plain text that says what the
  bot can do (answer questions, organize material, work on text), gives
  three ready-to-send examples such as “总结这份文件的重点”, and ends with
  a /help pointer — no Markdown tables, code markers or backend/command/
  preset jargon. The explicit `/help` command keeps the full dynamic
  command view, so the two layers serve different jobs. The WeChat welcome
  text is evaluated at send time through `getWeChatWelcomeText()` rather
  than a module-load constant, and the welcome path no longer pulls core
  imports at module scope, which also keeps `disclaude wechat status`
  stdout pure JSON: the illegal `silent` log-level fallback that leaked
  ConfigLoader info lines into the JSON output is gone.
- The Jupyter `tools` output now covers the whole command surface and the
  lifecycle commands speak JSON (#5321; #5706). `disclaude jupyter tools`
  lists all 21 Notebook commands, adding `check`, `link`, `create` and
  `unlink` with `type: object`, `additionalProperties: false` input
  schemas. `link`/`create`/`unlink` accept `--input-file` JSON
  (`{"path": "research/analysis.ipynb"}` via stdin with `-`), while
  `--path PATH` remains an equivalent shorthand; providing both or neither
  is rejected in argument parsing before any remote call, and invalid
  payloads (empty object, arrays, extra fields, non-string or
  out-of-scope paths) never reach the remote. Three long-standing
  behaviors are now stated where agents can find them — the phantom empty
  first cell of a fresh Notebook (empty-string SHA-256, surfaced through
  `removedSeedCellId` on first append), per-kernel FIFO execution with
  same-cell superseding, and `import-file`'s Project-relative single-file
  constraint — in the schema descriptions, the module README and the
  Jupyter skill, so callers stop rediscovering them by trial and error.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.16"
disclaude --version
```

Existing 0.6.15 deployments keep their configuration, registry and
workspace data; stop the running service before upgrading and run
`disclaude start` afterwards. Installation does not touch configuration or
workspace data. Use the [installation/rollback guide](git-install.md) to
switch releases; the prior package remains installed for rollback.

Automated coverage does not replace real-environment acceptance: real
first-message welcome delivery on a live WeChat/Feishu account and real
remote Jupyter lifecycle calls remain outside the automated test scope and
should be verified in your own environment.
