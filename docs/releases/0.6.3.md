# Disclaude 0.6.3: optional Datalayer Notebook research

The 2026-10-08 delivery uses the optional [Jupyter CLI/Skill](../jupyter-service.md)
merged in [#5282]. Agents discover the packaged Skill and invoke
`disclaude jupyter` through their existing shell tool. ChatAgent, its
factory/session pool, service startup and chat control have no Notebook
lifecycle dependency. Each command owns and closes its RTC sockets; Notebook
content and kernel memory remain on the configured remote Jupyter.

No `v0.6.3` tag or release has been published. [#5280] and [#5281] are the
remaining review PRs and both target main directly, with no stack. Foundations
[#5274]–[#5276], [#5278], [#5279] and [#5282] are merged. Coordinator [#5277],
aggregate [#5270] and overlapping preparation [#5257] are closed. See the
[review order](0.6.3-review.md) and [source-specific acceptance](0.6.3-acceptance.md).

## Intended changes

- Optional Notebook commands link/create a selected remote document, read/edit
  stable cells, import Project-local inputs, execute once and query/cancel an
  original run across independent CLI processes. Projects store references and
  original-run facts/results; they do not mirror Notebook content or own Python.
- Chat `/stop` stops inference only. `disclaude jupyter stop` explicitly
  targets the original notebookId/runId and reports `stopConfirmed: true`
  only after cancelled terminal evidence. It does not fall back to a kernel-wide
  interrupt. The proposed kernel interrupt command is follow-up [#5286].
- Native RTC, nbmodel requests and nbconvert supply live cells, retained original
  results and matching HTML/ipynb snapshots. `download-report` and
  `observe-image` materialize persistent Project artifacts with hashes and
  bounded raster files. Agents send these through the existing channel CLI with
  explicit chat/thread identity; ambiguous delivery is not blindly retried.
- Feishu attachment authentication, topic acknowledgements and report/image
  delivery repairs are merged. Notebook/HTML revision identity is separate from
  the exact file byte hash; nbformat line arrays/runtime trust are normalized
  without discarding other metadata or JSON outputs.
- The shared `ToolDefinition[]` and native image adapter foundation [#5244]
  remains separate from Notebook lifecycle. Harness configuration belongs in
  each adapter. DSH component probes may expose optional CLI-backed tools;
  their results do not establish production Skill discovery or Feishu acceptance.
- Valid Codex Sources contracts render as citation cards; unsupported/rejected
  cards fall back to text. This does not guarantee every model claim has the
  correct supporting source. Citation evidence remains tracked in [#5193].
- Completed Codex turn teardown and opt-in Feishu streaming authentication/message
  identity fixes remain part of the merged foundations. Prebuilt distributions
  omit Compose files with absent build inputs; this packaging repair does not
  add any Jupyter machine/container management capability.

Manual Lab parameter/Markdown editing and its human acceptance are outside
0.6.3 by the user's instruction. Existing preservation and RTC engineering
checks do not imply that the manual collaboration experience has been accepted.

## Runtime and compatibility

The host uses Node only. Python packages, scientific dependencies, kernels and
Notebook storage are managed by the existing remote Jupyter deployment.
Ordinary chat neither installs local Jupyter/Python nor opens a Jupyter connection.
The optional CLI uses the configured remote Datalayer/RTC/Contents/nbconvert
APIs; no disclaude_jupyter plugin or /api/disclaude endpoint is required.

Authentication supports environment, a host-private .env and hidden interactive
input. Agents use `--no-interactive`. Secrets, cookies and headers do not enter
model context, tool schemas, Project references or report links. Passwords stay
on the host. Capability discovery is connection evidence, not product acceptance.

Repair generation/deployment is `disclaude jupyter patch` through the selected
Jupyter's Terminal API. It discovers that environment and uses its manifest,
fingerprints, compatibility checks and rollback metadata. It supports no SSH,
Docker/container commands, fixed remote paths or automatic Jupyter service restart.
See the [Terminal patch guide](../../jupyter/datalayer/README.md).

The verified remote baseline includes MCP 2.2.3, nbmodel 0.2.9 and Lab 4.6.4;
record the actual compatible versions and repair manifest for release. Python
is the initial kernel language. A local per-Project command lock protects the
journal, but is not a server ownership fence or multi-client editing guarantee.
Observed source checks are client-side. Unknown submissions are never replayed;
retention expiry, original request loss and kernel/Jupyter memory loss remain
explicit unknown/lost conditions, without creating a replacement kernel.

## Gates before publication

- [ ] Review #5280/#5281 and record the actual combined source, remote dependency/
      configuration/repair versions, Terminal installation and rollback evidence.
- [ ] Verify configured-server output persistence, non-consuming original result
      recovery, cancellation/next-run isolation, source attribution and MIME clear
      semantics against that source, retaining failed checks and retention limits.
- [ ] Verify the required current-source model/Feishu Project flow, attachment
      input, explicit original-run stop, same-kernel continuation and exact-thread
      artifact delivery. Inference stop and remote cancellation are separate.
- [ ] Verify original requests in new CLI processes, reply/auth failures, lost
      acceptance and owned kernel memory loss without replay. Injected faults are
      labelled; Jupyter service restart remains unverified on the updated API-only
      probe and has no automated deployment path.
- [ ] Keep device/HTML/Plotly interaction and citation checks scoped to their actual
      sources. HTTP headers, file hashes and historical overall display feedback
      do not substitute for unobserved device behavior or source semantics.
- [ ] Record data/environment/seeds and numerical reproduction in fresh remote
      kernels; do not claim byte reproducibility for runtime IDs/SVG dates/paths.
- [ ] Run regression, type/lint/build and standalone archive installation on the
      exact final merged source. Check version/lockfile and record release-source
      provenance, fingerprint and artifact hash. Historical RC hashes are not reused.
- [ ] Maintainer decides merge, tag and publication after applicable gates pass;
      the [installation and rollback guide](git-install.md) remains authoritative.

Real candidate windows preserve configuration/workspace, use one bot connection,
and restore the original healthy service. Updating these PRs does not switch
production, close outstanding issues, merge a PR or publish a release.
