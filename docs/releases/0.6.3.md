# Disclaude 0.6.3: Datalayer Notebook research

The delivery plan was revised on 2026-10-06 to use Datalayer interfaces and a
thin Node adapter. No `v0.6.3` tag or release has been published. The configured
server has passed the six server-side repair scenarios through recorded component
probes. Real Project/Feishu, native Lab/device and final-source release acceptance
remain open. See the
[delivery design](../designs/jupyter-harness.md) and
[configured-instance evidence](../designs/datalayer-mvp.md).

## Intended changes

- Business agents provide one `tools: ToolDefinition[]` contract. Harness
  registration and configuration stay in each adapter; Claude tool allow/deny
  lists belong only to the Claude provider. DSH keeps durable sessions and
  cancellation across continuation. This foundation is merged in [#5244].
- Existing Projects continue research in the same remote Notebook through
  native RTC, nbmodel execution/requests and official nbconvert. Humans edit
  live parameters and prose in Lab; the Agent preserves those edits. Planned
  delivery includes browser-closed output saving, target-specific stop,
  original-request recovery and matching Notebook/HTML/Feishu artifacts.
- Codex answers with a valid Sources contract can render as Feishu citation
  cards. Prompts guide evidence and source placement; parsing or a known card
  rejection falls back to text. This does not guarantee that every initial
  model claim has the correct supporting source.
- Closing an already completed Codex turn performs teardown without reporting
  a no-active-turn error. Steering an idle session still reports actionable
  diagnostics.
- Prebuilt distributions omit Compose files whose build inputs are absent.
  Docker/Compose deployment uses a source checkout, as described in the
  [deployment guide](../docker-compose-deployment.md).
- Notebook report delivery uses temporary host copies of one verified remote
  snapshot, returning actual channel message IDs and file hashes. The generic
  file callback retains the original thread; bounded raster previews accompany
  matching ipynb/HTML files. Unconfirmed delivery is reported without automatic
  retry. This path still requires real Agent and actual-device acceptance.
- Feishu command acknowledgements retain the incoming topic root. Attachment
  downloads obtain current bot authentication from the channel SDK and give
  the CLI a relative output path; no startup token is required. These repairs
  address failures from the actual candidate Service window, with product
  reacceptance tracked separately from unit checks.
- Report revisions normalize native nbformat line arrays and code-cell runtime
  trust flags. Other metadata and JSON outputs remain checked. The uploaded
  ipynb is the exact authenticated remote file, with its byte hash recorded
  separately from the logical revision. This corrects a real Service export
  failure; the failed delivery is retained pending product reacceptance.

## Runtime and compatibility

The disclaude host uses Node to connect to the configured remote Jupyter.
Python packages, kernels, scientific dependencies and Notebook storage belong
to that remote deployment.
Ordinary chat installation does not install or start a local Python/Jupyter
environment. The adapter now defaults to Datalayer when `backend` is omitted;
explicit `backend: "coordinator"` preserves the historical backend and cookie
identity. Host inspection reports interface/configuration evidence separately
from product acceptance. Reference migration, Lab Run routing, deployment
acceptance and final-combination repair acceptance remain release work; the default change does
not complete #5216.
The tested remote baseline includes MCP 2.2.3, nbmodel 0.2.9 and Lab 4.6.4.
Pin a verified compatible deployment; the old coordinator profile's exact
version gate is not a Datalayer requirement.

Authentication remains host-owned. Passwords, cookies and authorization headers
must not reach model input, tool declarations, Project references or report
links. Datalayer does not require `disclaude_jupyter` or `/api/disclaude`.
Capability discovery and successful authentication do not establish product acceptance.

The first release supports Python and one Service writer. It checks observed
source hashes and original request/kernel identities, and never automatically
replays an uncertain execution. Kernel/Jupyter restarts may lose memory or an
unconfirmed result; report that loss. Multi-controller isolation, atomic editing
and a permanent late-submission fence are evaluated in [#5267], outside this
milestone. MCP Tasks and complete widget/comm export are not prerequisites.

## Gates before publication

- [ ] Review the revised changes and record the actual final source and remote
      dependency/configuration/patch versions; verify deployment and rollback.
- [ ] Reproduce and pass all six behavior failures through #5262–#5266 on the
      configured remote server, including cancellation/next-run races.
- [ ] On that configured server, verify shared human Markdown/parameter edits,
      live RTC edits, Lab/Agent serialized entry, browser-closed output saving, exact stop and
      continuation in the original Project and Feishu thread.
- [ ] Verify original-request recovery in a new Agent process, network/auth
      failures and kernel/Jupyter restarts without blind replay. Unknown memory
      or results remain unknown. Verify stdin behavior or explicit rejection.
- [ ] Inspect rendered charts/formulas/report and open the authenticated
      Notebook/HTML delivery on the actual device; all outputs must match one
      recorded Notebook revision. Cover formulas, tables, PNG/SVG/HTML and a
      Plotly example, authenticated device access, HTML sanitizer/CSP and complete
      artifact references beyond bounded previews.
- [ ] Complete citation-card P2P streaming message identity and real plain-text
      channel fallback checks, retaining the earlier semantic-source failures in
      [#5193]'s evidence scope; feature merge alone does not complete that task.
- [ ] Record data/environment/seeds and verify the claimed reproducibility range
      in a clean remote kernel, retaining any qualitative sources and limitations.
- [ ] Run full regression, type/lint/build and clean installation on the exact
      final merged source; build the prebuilt distribution and record its
      `release-source.json` provenance and fingerprint.
- [ ] Publish only after maintainer review and all applicable product gates.
      The [installation and rollback guide](git-install.md) remains authoritative.

Component tests, isolated CLI checks and earlier protocol experiments are
engineering evidence. They do not complete the remote Notebook/Project/Feishu
product gates above. Production candidate windows preserve configuration and
workspace, use a single bot connection, and restore the original healthy service.
