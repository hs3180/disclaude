# Disclaude 0.6.22: delivery observability and on-demand research watching

Release preparation, 2026-11-09. This patch release packages the reviewed
runtime at main `ec65e27c8`. The four merged changes since 0.6.21 make media
delivery and progress observable (WeChat upload phases with a stall watchdog,
layered delivery accounting with a heartbeat backstop, real delivery-position
receipts for channel CLI sends) and add on-demand watching for comments left
on research output documents. Release preparation changes only version
metadata and documentation beyond those scoped changes. The final source
commit, archive, checksums, and fresh installation results are recorded in
the release assets.

## Changes

- WeChat media uploads now time the CDN link in phases — connect (incl.
  TLS), write, and response — each recorded separately (#5720; #5728). A 10s
  connect budget and a 15s stall watchdog abort a stuck upload early instead
  of waiting for the overall size-aware deadline; a zero-byte failure during
  connect (nothing written server-side) is retried once only when the cause
  is known to be side-effect free. Upload errors carry the phase, per-phase
  durations, and byte lengths — never payload content — so "cannot reach the
  CDN", "cannot write", and "no response" are distinguishable in reports.
- Long turns keep a heartbeat even if the turn-driven chain goes silent: a
  30s timer backstop detects heartbeat silence and sends the missing beat
  under duplicate-send guards (no send between turns that already delivered,
  no send without liveness evidence, no send after dispose, serialized
  sending) (#5719; #5729). Delivery progress is now layered accounting —
  send attempt, then platform result — and WeChat attachment delivery
  reports attempt, upload result, and send result as separate events; where
  the platform cannot confirm phone-side receipt, that is stated explicitly
  (`unverifiable_server_side`) instead of implying the user saw the message.
  Progress records carry only message kind and length, not content.
- Channel CLI receipts disclose where a message actually landed:
  `send_file`, `send_text`, and `send_card` echo `thread reply to <root>`
  or `chat root` together with the message id, the upload handler returns
  `messageId`/`deliveryPosition`/`threadId`/`rootId` end to end over the
  REST protocol (optional fields; older clients unaffected), and sending to
  a topic group without `--parent` prints an explicit warning while still
  sending (#5722; #5730).
- Research document comments can now be watched on demand (#5197; #5708).
  `disclaude research watch start [--interval SEC]` / `stop` / `status`
  host a bounded watch session over the explicit `research-doc-watch`
  registry — documents a Research context deliberately associated with a
  Project chat. Sessions keep per-document checkpoints and restart-safe
  deduplication, back off per document on failures, and surface errors via
  `status`; new comment batches are routed to the original Project chat's
  agent, which stays in charge of adopting, questioning, or declining them.
  Nothing is constructed or scheduled while no session is running, and the
  watcher never edits documents or replies to comments.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.22"
disclaude --version
```

**Upgrade note.** No configuration migration is required; 0.6.22 is a
drop-in replacement for 0.6.21. Existing deployments keep their
configuration, registry, and workspace data; stop the running service
before upgrading and run `disclaude start` afterwards. Installation does
not touch configuration or workspace data. The new upload budgets, delivery
accounting, receipt positions, and research watching all apply without
configuration changes; the research watch registry lives under
`workspace/.disclaude/research-doc-watch/` and is only read while a watch
session is running. Use the [installation/rollback guide](git-install.md)
to switch releases; the prior package remains installed for rollback.
