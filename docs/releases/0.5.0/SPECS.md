## S01 — 命名预设与会话内选择

入口：`packages/core/src/config/`、`sdk/factory.ts`、`sdk/interface.ts`、`control/`，`packages/primary-node/src/agents/factory.ts` 与 Agent pool。

交付：预设 schema、唯一默认规则、旧配置兼容、查看/切换命令、后端能力矩阵。先确定 chat/session 作用域、配置持久化边界和忙碌会话切换策略；将这些契约交给 S02/S03/S06。pi 从现有 provider 起步做验收。

验收：

- A1：命名预设、唯一默认、旧 `agent:` 配置有测试；重复/缺失默认、未知后端、非法组合给出可操作错误。
- A2：成功切换显示实际生效 backend/model；切换失败保持原会话可用；不支持热切换时明确新会话边界，不承诺跨后端原生上下文迁移。
- A3：不同 chat 的选择互不影响；忙碌会话的排队/拒绝行为有明确回归，不能将正在执行的回合偷偷换后端。
- A4：Claude/Codex/pi 的已支持能力与实测一致；pi 现有工具路径和拒绝行为不回退，不重新引入外部 MCP 适配器。

证据：配置样例、命令成功/失败记录、会话隔离回归、按后端列出的已测与未测项。命令最终语法写入使用文档，不把 Issue 示例视为既定接口。

## S02 — DeepSeek harness

入口：`packages/core/src/sdk/providers/`、`sdk/factory.ts`、配置层；新增 provider 目录由实现确定。

交付：先核实 dsh 安装、认证与 stdio JSON-RPC 协议，记录经验证版本与原始事件样例，再按配置 → 传输与生命周期 → 事件映射 → 工具/通道 → E2E 分增量落地。

验收：

- A1：缺少二进制、认证或配置错误时启动前给出明确诊断，原有后端仍可用。
- A2：请求与响应按 ID 关联，覆盖分片、连续帧、异常帧、EOF、进程失败、取消及资源清理；协议细节以实测和官方定义为准。
- A3：文本、工具事件、完成与失败映射到统一事件语义，不重复结算或重复发送最终结果。
- A4：真实后端能完成单轮、多轮、工具调用和一次飞书最终交付；验证工具确实执行，不能仅检查接收确认。
- A5：错误和取消路径可回归，现有 Claude/Codex/pi 行为不被破坏；配置与使用文档完整。

证据：脱敏协议 fixture、适配测试、真实后端版本/运行记录、工具产物及投递回执。dsh 不可用时可完成契约测试，但此包保持未验收；不以模拟 provider 宣称接入完成。

## S03 — 回合身份与运行中控制

入口：`packages/primary-node/src/agents/chat-agent.ts`、`packages/core/src/task/`、`sdk/providers/codex/`、控制命令和调度调用边界。

交付：先修正 FIFO 结算为有身份的回合结算契约，再实现 Codex stop/queue/steer。明确输入 messageId、执行标识、重试 attempt 和最终通知的对应关系，为 S04/S06 提供单一结算入口。

验收：

- A1：A/B 并发、B 先完成、A 被取消、超时后的迟到完成均正确归属；重复完成只结算一次，不把下一条任务的结果结算给前一条。
- A2：停止确认后不派发新工具调用，取消旧 attempt 的重试和输出路径；记录确认/退出延迟以及无法立即中止的工具边界。
- A3：追加消息排队不取消当前回合；steer 确实影响后续执行并确认生效，不能仅改消息文案假装立即纠偏。
- A4：打断后可继续追问；覆盖工具执行、重试、失败与恢复场景，不把 stop 实现成无提示销毁全部会话。
- A5：不支持某种运行中控制的后端明确返回能力限制，已完成或未知回合的控制命令幂等且可解释。

证据：乱序与重复事件序列测试、真实 Codex 工具运行中控制记录、取消延迟及后续调用日志。平台/CLI 上游不具备 steer 能力时记录阻塞，不能偷偷降级为普通排队后关闭 Issue。

## S04 — 流式与最终交付

入口：ChatAgent 流处理、飞书 messaging adapter/Card Kit client、每会话 throttle 和日志事件。

交付：审计已有 Card Kit/节流实现，补齐 thinking → replying → done 状态机、普通消息降级、工具噪声过滤、可诊断的未知错误和原子消息去重。所有终态消费 S03 的回合身份。

验收：

- A1：正常路径在同一张卡片更新和收尾，思考到回复有明确转换；不同会话的节流状态互不影响，结束后释放资源。
- A2：429、缺失回调、更新抛错和 finalize 失败均有可观察降级，最终内容不丢；不重复把同一终态当新回复发送。
- A3：正常完成、工具后无正文、未知错误、取消等情况都向用户交付明确终态，不能把“provider 结束”当成“用户已收到”。
- A4：过滤不必要的工具过程消息仍保留完整诊断；通过输入/回合/投递标识能定位丢失环节，重复飞书事件不会并发执行两次。
- A5：采用 #4398 最新决策允许的节流参数，记录依据和实测边界；不重新强制已否决的 pre-ship benchmark。

证据：状态机与故障回归、并发去重测试、真实飞书卡片/普通消息回执、脱敏日志。只验证 HTTP 接收成功不足以证明最终投递。

## S05 — CLI 与动态内部端口

入口：`packages/channel-cli/`、`bin/disclaude.js`、REST client/server、Primary 启动入口、`scripts/launchd.mjs`、Docker 配置。

交付：先核对已迁移 push 实现，统一实际 `disclaude channel` 子命令；打包后可独立调用；内部服务随机监听并向受管客户端传递实际地址。

验收：

- A1：打包产物在仓库外的干净目录安装后可运行 help、发送与 push，不依赖源码相对路径或开发机 PATH。
- A2：同主机两个实例均可启动并使用各自端口，固定历史端口被占用不影响启动；测试必须实际启动实例而非只断言配置文本。
- A3：启动就绪后才传递地址，子进程携带正确地址及原有认证；服务重启后受管客户端不会继续使用旧端口。
- A4：区分受管子进程和独立启动 CLI/跨容器客户端，给出后者可用的地址配置方式；不能假设环境变量可逆向更新父进程或自动跨容器传播。
- A5：非法/缺失地址有明确错误，日志不泄露 token；迁移文档和测试删除固定默认值依赖，公开 HTTP 入口是否固定与内部端口分开说明。

证据：打包安装测试、双实例/重启回归、跨 cwd 调用、认证失败记录。使用隔离端口与测试目录，不重启现网服务。

## S06 — 调度与上下文

入口：`packages/core/src/scheduling/`、`packages/primary-node/src/agents/history-manager.ts`、ChatAgent、`skills/schedule/` 与相应模板。

交付：脚本/提示调度互斥校验，脚本按需 push；明确 fresh session/history skip/兼容 clearContext 语义；历史仅按实例首次注入；账本有界归档；修复非法 modelTier 静默回落。

验收：

- A1：无变化轮询零 LLM 调用，有变化经 S05 入口唤醒且最终交付；两种调度模式均覆盖 blocking/cooldown/timezone/timeout/失败计数。
- A2：脚本退出码、stdout/stderr 和超时可定位；明确“停止等待”和“终止进程”的区别，取消与迟到结果消费 S03 的标识。
- A3：默认调度不累积无界 live session；调度执行前后用户会话、历史快照和恢复行为有矩阵及迁移说明，不能无提示破坏用户正在进行的会话。
- A4：多轮 tick 和实例恢复下历史注入次数及大小符合配置；账本超过保留阈值后幂等归档，无丢失、无重复归档，不重新全文读入归档。
- A5：合法模型设置实际生效；非法 tier 或预设明确报错/提示，不悄悄改用默认模型；与 S01 预设规则兼容。

证据：空轮询调用计数、真实有变化唤醒、并发/超时回归、逐轮上下文大小记录、归档前后内容核对、旧配置迁移样例。界限验证用可控多轮测试，不能拿压缩后的单轮大小代替增长测试。

## S07 — Harness 收敛与升级

入口：Claude provider/options/message adapter、BaseAgent、MessageBuilder、配置和 lockfile。

交付：审计 #4811 目标版本及兼容性；按其最新决策升级 SDK。逐项列出 workaround 的原始问题、上游是否已解决、保留/删除理由；稳定提示与动态信息分离，清理失效 GLM endpoint。

验收：

- A1：升级后的构建、类型与相关 provider 回归通过；版本和内嵌 CLI 以实际依赖为准，不把本机全局 CLI 当 SDK 运行版本。
- A2：每个保留 workaround 有来源、单一入口及配置/适用条件；删除项有问题已消失的证据，不能因“代码复杂”删除仍必要的恢复机制。
- A3：瞬态错误、空流、中断和未知异常仍满足 S03/S04 终态契约，不新增重复 retry/watchdog 链。
- A4：稳定前缀与逐轮动态内容分离有输入对比证据；若不能测真实 cache hit，明确只完成结构验证，不编造缓存收益。
- A5：配置、模板、测试中的失效 endpoint 引用一致清理；旧配置失败有迁移提示；调度上下文仍通过 S06 回归。

证据：升级前后依赖版本、workaround 审计表、输入结构差异和相关测试。与 ChatAgent/历史模块的其他变更以合并前置为基线，避免重叠重构。

## S08 — 隔离与运维

入口：项目 cwd provider/Agent 创建链、`packages/core/src/utils/logger.ts`、Docker/launchd 配置、README/quickstart/环境变量文档。

交付：确保绑定项目实际 cwd 正确，明确不存在目录的处理；验证已有日志轮转与 stdout 镜像；清除失效 PM2 指令，统一安装和启动路径。

验收：

- A1：两个项目实例、缺失目录、重启和项目切换均核对 SDK 实际 cwd；不能无提示回落共享 workspace 后继续写文件。
- A2：在隔离日志目录触发轮转，保留量有界；文件与 stdout 均可见，进程退出后日志完整；不使用现有 49GB 日志做破坏性试验。
- A3：#4814 等已合入实现优先验收；仅存在缺口时改代码，不重复实现轮转或镜像。
- A4：新环境照 Docker/macOS launchd 文档完成安装、启动、状态查询和停止；命令确实存在，文档不残留 PM2 为支持方案的表述。

证据：实际 cwd 产物、轮转数量/大小及 stdout 样例、两种部署方式的验证记录。无 macOS 或 Docker 环境时将对应项标为未验证，留给 S09 补齐。

## S09 — RC 与发布准备

入口：上述工作包证据、CI、`tests/integration/`、`package.json`、发布 workflow、README/CHANGELOG 和版本信息。

交付：选定单一候选 SHA，汇总所有 P0 验收和配套结论，整理实际变更、升级/回退步骤及已知限制。父 Issue 关闭数量不得代替证据。

验收：

- A1：37 个 Issue 均能追到主责 SPEC、代码/PR 和验收结论；P0 无延期，配套延期如有则有明确接受记录，不将缺失证据标为通过。
- A2：在候选 SHA 上必需 CI 全绿；正式后端的对话/工具/异常/最终交付、切换失败、停止/steer、卡片降级、脚本唤醒、并发结算和多实例均有证据。
- A3：相关变更合并后重新核验受影响场景；旧 SHA 的证据只有确认未受影响才能复用，不能笼统宣称整版通过。
- A4：Docker 与 macOS launchd 的新安装、升级、回退演练通过；使用隔离实例和备份状态，不影响用户现有服务。
- A5：解决根包 private 与 npm publish workflow 的冲突：先确认实际分发渠道，再对打包/发布配置做 dry-run 或静态验证；真实发包不作为测试。
- A6：会话/项目串扰、停止失效、静默丢结果和任务错配为零；Changelog 只列实际交付，Research 等 P1 明确是否随版提供。

证据：`release-candidate.md`（候选 SHA、后端/部署矩阵、检查命令与退出码、证据路径、迁移与回退、限制、阻塞项）。满足后回报 RELEASE_READY；真实版本更新、tag、Release、发包和部署只在相应发布授权下执行。
