# Disclaude 0.6.11: background-agent completion, notebook delivery polish, media-upload reliability

Release preparation, 2026-11-05. This patch release packages the reviewed
runtime at main `f54277dac`, which carries thirteen changes beyond the
0.6.10 source: eleven user-visible fixes and additions — background
subagent completion no longer masked (#5330; #5631), notebook delivery
polish (empty first cell removal #5548; #5633, source-hidden code cells
#5615; #5663), browser-control self-healing after restarts (#5427; #5660),
topic-routed busy receipts (#5435; #5667), structured forensics for channel
HTTP failures (#5655; #5670), a heartbeat for narration-silent turns plus
side-effect receipts on failure (#5654; #5671), WeChat media upload over
`node:https` with size-based deadlines (#5516; #5672), duplicate-question
suppression for consumed attachments (#5434; #5674), safe continuation
guidance for WeChat re-login identity changes (#5480; #5662), claude
AskUserQuestion bridged to the host input channel (#5613; #5676), and the
documented WeChat typing refresh cadence (#5471; #5647) — plus one
test-hygiene fix (#5675). Release preparation changes only version metadata
and documentation beyond main.

Generated with the hardened release pipeline introduced in 0.6.8 (#5517,
#5522): stale build artifacts are pruned, the runtime is rebuilt from
source with `tsc --build --force`, the build asserts the source tree did
not change, and `release-source.json` records build provenance.

## Changes

- **Background subagents report completion again**: a background agent
  spawned by a main turn and finished after `end_turn` now delivers its
  terminal notification — the snapshot path no longer swallows it, and the
  pending-continuation latch clears, so the session stops answering "still
  busy" to new messages for half an hour while 25 minutes of work silently
  sat finished (#5330; #5631).
- **Delivered notebooks open on content**: the RTC-seeded empty first cell
  is removed when the first user cell is appended (#5548; #5633), and code
  cells are collapsed by default through the standard
  `jupyter.source_hidden` metadata so readers see text and outputs first,
  one click away from the source (#5615; #5663). Markdown cells and export
  fidelity are unchanged.
- **Browser control self-heals after a browser restart**: the cached CDP
  WebSocket identity is validated against the live `/json/version` before
  every attach; on drift the client re-discovers, migrates the runtime
  manifest and injects the fresh identity, instead of persisting 404s
  until a human refreshes the runtime config (#5427; #5660).
- **One task, one topic**: busy-time supplemental receipts follow the
  anchor the running turn's replies actually used, so confirmations like
  "🎯 后端已确认接收…" land in the thread they belong to instead of
  fragmenting the main chat (#5435; #5667).
- **Channel HTTP failures leave evidence**: method, URL, status,
  allowlisted headers and a truncated sanitized response body are logged
  on failure, and Feishu business error codes/messages are attached to the
  error string so notifications carry the internal error code
  (#5655; #5670).
- **Silent long turns stay observable**: when a turn has produced no
  user-visible progress for five minutes while tools keep running, a
  lightweight heartbeat reports runtime, silence and call count; when a
  turn fails, a closing receipt lists the tools it already ran (name and
  count only) so finished side effects are not lost (#5654; #5671).
- **WeChat media uploads stop timing out on large videos**: uploads move
  to a `node:https` channel with a size-derived deadline (~250KiB/s floor,
  ≈77s for a 15MiB payload) instead of a flat 15s abort, fixing
  intermittent CDN upload failures for ~15MB videos; the #5625 diagnostic
  surface is preserved (#5516; #5672).
- **Consumed attachments stop re-asking**: attachments already consumed by
  a running request — including ones that sat in the channel FIFO queue —
  no longer trigger a duplicate recognition-and-question turn after the
  main answer was delivered (#5434; #5674).
- **WeChat re-login with a new bot id explains itself**: identity checks
  are not relaxed, but the error now describes the old/new identity
  difference and, when the WeChat-server user id matches, points at a
  plain-login continuation path instead of a bare rejection (#5480;
  #5662).
- **claude sessions can ask structured questions**: the claude backend's
  AskUserQuestion tool is bridged to the host input channel through the
  persisted task-question admission flow, so multiple-choice and
  confirmation questions render as channel cards and answers return to
  the model; without an input channel the tool stays disabled and behavior
  is unchanged (#5613; #5676).
- **Typing cadence documented**: the WeChat "typing…" refresh constants
  (5s refresh / 30s failure backoff) are named and documented with their
  trade-offs (#5471; #5647).
- **Test hygiene only**: the goal-execution-service status-transition test
  waits for the persisted terminal condition instead of a fixed timer
  drain (#5675). No runtime behavior change.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.11"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards
with `disclaude start`. The installation does not modify configuration or
workspace data. Existing 0.6.8–0.6.10 deployments keep their configuration
and workspace data; use the [installation/rollback guide](git-install.md)
to switch releases.
