## HTML 导出策略实测

配置实例通过真实 `POST /nbconvert/html` 导出一份自有、无害的 Markdown/输出
HTML fixture，再从受认证的 `/files` 下载并比较字节。Markdown script、event
属性和输出 script 均保留；匿名请求为 302，响应 CSP 为 `sandbox allow-scripts`，
未声明 `allow-same-origin`。这是保留动态内容的原生 HTML 报告导出，
不把它称为清除脚本的静态预览。官方 [nbconvert 配置说明](https://nbconvert.readthedocs.io/en/v7.17.0/config_options.html)
也将 `HTMLExporter.sanitize_html` 的默认值列为 false。下载的 HTML 文件与远端
带响应头的预览分别记录；浏览器隔离和各项交互没有由 HTTP 证据替代验收。

该 fixture 没有启动 kernel，没有访问用户 Notebook 内容。核验后仅删除自有临时
远端 HTML，保留私有原始 HTML/指纹。再次核验恢复健康、325 行身份指纹、报告
字节和 10 个引用均通过。用户的整体显示反馈见上文；没有反推专项 JavaScript 行为。
