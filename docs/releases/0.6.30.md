# Disclaude 0.6.30: orthogonal `/agent` backend/model switching and native DSH skill delivery

Release preparation, 2026-11-26. This patch release packages the reviewed
runtime at main `b020cbd25`. Two merged changes ship since 0.6.29: `/agent`
switches the harness (backend) and the model as two independent dimensions
and the named agent-preset concept is retired (#5255; #5723), and the
DeepSeek Harness channel delivers built-in skills through the harness's
own skill discovery instead of a prompt-side skill list (#5717; #5726).
Release preparation changes only version metadata and documentation beyond
those reviewed changes.

## Changes

- Split `/agent` switching into two orthogonal dimensions — harness
  (backend) and model — and remove the named agent-preset concept
  (#5255; #5723). The `agents:` key domain is now the harness name
  (`claude`, `pi`, `codex`, `dsh`, `miniswe`); each entry is that harness's
  default binding with an optional `model` pin that outranks
  `llms.<llm>.defaultModel`, and the per-entry `backend` key is rejected at
  load. A new top-level `defaultHarness` names the binding used by chats
  that have not selected one (a dangling reference is a structured load
  error), and `channels.<name>.agent` references a harness id.
  `/agent backend [name]` and `/agent model [name]` show the current value
  and the available options when called without an argument and switch
  exactly one dimension when called with one; `/agent use <harness> [model]`
  sets the harness (and optionally the model) and persists per chat across
  service restarts, while the per-dimension overrides are in-memory and
  fall back to the configured default on restart. Switches are validated
  against the harness x LLM compatibility matrix (claude accepts only the
  Anthropic protocol, pi accepts both, dsh and miniswe need protocol and
  base URL, codex uses an OpenAI Responses binding or its own ChatGPT
  login), and an invalid combination returns the options for that dimension
  instead of taking effect silently. The Feishu configuration card switches
  per dimension with runtime wording; the control ports are renamed to
  `listAgentRuntimes` / `getActiveAgentRuntime` / `switchAgentRuntime` and
  the types to `AgentRuntime(s)`.
- Deliver built-in skills to the DeepSeek Harness (DSH) channel through
  native harness discovery (#5717; #5726). The standard `sdk` profile
  receives a profile overlay that enables `@deepseek-ai/dsh-skill-filesystem`
  with `bundledSkillDir` pointed at the built-in skills directory, ranked
  below project and user skill roots; a user profile that already carries
  the plugin keeps its own configuration keys, and the user profile file is
  never rewritten. Profiles that verifiably have no skill stack (such as
  `sdk-minimal`) receive no overlay: combining one with the explicitly
  installed diagnostics plugin still fails fast before spawn with an
  actionable remedy, and when a custom profile reports no skill capability
  after initialize the provider raises an actionable error instead of
  silently degrading. Disclaude no longer parses `SKILL.md` manifests to
  build a DSH skill list, and no Disclaude-assembled skill list reaches the
  model input on any path. The host-side skills registry keeps a single
  strict `parseSkillDocument` parser shared by discovery and body loading.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.30"
disclaude --version
```

**Upgrade note.** Deployments that declare `agents:` presets must migrate
their configuration before starting 0.6.30: rename each `agents:` key to
its harness name (`claude`, `pi`, `codex`, `dsh`, `miniswe`), drop the
per-entry `backend` key (the loader rejects `agents.<name>.backend`), and
name the chat default with the top-level `defaultHarness`, and make
`channels.<name>.agent` values harness ids. Configurations without an
`agents:` block keep the legacy single-agent path. In-chat, `/agent use`
now takes a harness name and an optional model. The committed
`disclaude.config.example.yaml` still shows the earlier preset-style
`agents:` block; follow the key-domain rule above rather than copying it.
The DSH skill delivery change needs no configuration. Stop the running
service before upgrading and run `disclaude start` afterwards; installation
does not touch configuration, credentials, or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the prior
package remains installed for rollback.
