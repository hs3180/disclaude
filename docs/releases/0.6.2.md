# Disclaude 0.6.2

0.6.2 tightens scheduling and Claude stream reliability, makes follow-up
suggestions more useful, and adds focused Codex and Chromium diagnostics.

## Highlights

- **Schedule reliability:** invalid schedule configuration and registration
  failures produce actionable, deduplicated diagnostics in the configured task
  chat. A changed owner can receive a still-relevant warning.
- **Claude stream recovery:** the Claude SDK owns stream retry decisions while
  Disclaude continues to settle explicit failures and completed empty streams.
- **Contextual next steps:** after completing a request, the agent can suggest
  one concrete optional continuation grounded in the user's goal and conversation
  context. It does not start optional work before the user chooses.
- **Codex configuration:** set the Codex model and reasoning effort together,
  with clear precedence and diagnostics for unsupported values.
- **Chromium diagnostics:** `disclaude chromium-cdp status|doctor` reports the
  selected browser, Profile path, managed service state, and CDP reachability
  without changing configuration or starting services.
- **Workflow guidance:** schedule command/prompt modes and Research full-document
  commenter notifications now have clearer operating instructions.

## Compatibility and boundaries

- The prebuilt distribution is installed from the `v0.6.2` GitHub tag. See the
  [installation and rollback guide](git-install.md). The source package remains
  private and is not published to the npm registry.
- Chromium status/doctor is a read-only diagnostic slice. It does not provide
  interactive browser installation, Profile migration, or login-state migration,
  and it does not complete the full #4828 request.
- Research-comment notification and schedule-owner alert flows still require
  real Feishu/Project acceptance. The Research change is guidance and protocol
  support; this release does not claim that the complete user-visible workflow
  has been validated.
- Codex citation-source mapping is not included. The current app-server protocol
  does not expose a verifiable mapping between answer spans and source URLs.
- Full suite, type-check, lint, build, and prebuilt-package installation results
  are recorded against the exact source revision in the published GitHub release
  and its `release-source.json` provenance manifest.
