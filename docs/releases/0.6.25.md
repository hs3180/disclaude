# Disclaude 0.6.25: explicit chatgpt vs API LLM access for Codex

Release preparation, 2026-11-09. This patch release packages the reviewed
runtime at main `e10918a006`. One merged change ships since 0.6.24: the
`llms.<name>.via` access dimension that defines ChatGPT subscription login
and compatible API credentials as distinct, explicit LLM access methods for
the Codex runtime (#5338; #5724). Release preparation changes only version
metadata and documentation beyond those reviewed changes.

## Changes

- Config: declare the LLM access method with `llms.<name>.via`
  (`chatgpt` | `api`) (#5338; #5724). `chatgpt` — the default when an LLM
  has no `api` block — uses the Codex-managed ChatGPT login and
  subscription quota and keeps the existing login-missing, reauth, and
  weekly-quota diagnostics; it is only available to the codex backend. The
  explicit `api` method binds the same codex runtime to an
  OpenAI-protocol (Responses) endpoint, injected as a namespaced upstream
  `model_providers` entry whose credentials travel only through the child
  process environment. The two paths never silently fall back to one
  another: `via: api` without an `api` block, `via: chatgpt` alongside an
  `api` block, non-codex backends bound to `chatgpt`, and mixed or
  unsupported protocol combinations fail at configuration time with
  actionable errors. LLM entries that omit `via` keep their previous
  meaning, and legacy `api`-block configurations keep resolving exactly as
  before. Service startup probes now receive the resolved agent
  configuration and no longer misreport under an API-bound access method.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.25"
disclaude --version
```

**Upgrade note.** No configuration migration is required. Existing LLM
entries keep working unchanged: `via` is opt-in per named LLM, and its
default follows today's behavior (an `api` block stays API access; without
one, the ChatGPT login path). Stop the running service before upgrading
and run `disclaude start` afterwards; installation does not touch
configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the
prior package remains installed for rollback.
