# Disclaude 0.6.10: visible input consumption, best-effort scheduler notices, push-session question alignment

Release preparation, 2026-11-04. This patch release packages the reviewed
runtime at main `8a54a9b0a9c5`, which carries five changes beyond the 0.6.9
source: three user-visible fixes — input-consumption visibility for busy
sessions (#5470; #5666), best-effort informational notices in the scheduler
(#5656; #5669), and structured handling of rejected blocking questions in
push-initialized sessions (#5430; #5668) — plus two test-hygiene fixes that
put main Unit Tests back to green on consecutive batches (#5648, #5673).
Release preparation changes only version metadata and documentation beyond
main.

Generated with the hardened release pipeline introduced in 0.6.8 (#5517,
#5522): stale build artifacts are pruned, the runtime is rebuilt from source
with `tsc --build --force`, the build asserts the source tree did not
change, and `release-source.json` records build provenance.

## Changes

- **Input consumption is visible while a turn is busy**: when a queued input
  is picked up for execution, the session emits a `▶️ 已取用…` receipt
  anchored to that exact input, and admission receipts now name the
  attachments carried along ("N 个附件，将随这条输入一起处理"). A user
  waiting behind a long turn can tell their message was consumed instead of
  re-sending it; this completes the remaining openness items of #5470 on top
  of the delivery-circuit recovery shipped in 0.6.8 (#5470; #5666).
- **Scheduler informational notices are best-effort, never task failures**:
  a transient send failure of the "⏰ …开始执行" opening notice — or of the
  other purely informational notices (command opening notice, cooldown-skip
  notice, unconfigured-router warning) — is logged and skipped; the task
  still routes and runs, and the failure does not increment the task's
  consecutive-failure counter. Task-body failure accounting is unchanged:
  a genuinely failed run is still reported and counted (#5656; #5669).
- **Push sessions handle rejected blocking questions like ordinary
  sessions**: a host-side rejection of a blocking async question — for
  example a push-initialized turn with no interactive input context, or a
  blocking card whose delivery failed — is now recorded as the structured
  local input-delivery failure of #5526 (terminal turn state preserved,
  exactly one notice) instead of an unlabelled protocol cancellation, so a
  turn that already delivered its work is no longer mislabeled
  provider-turn-failed (#5430; #5668).
- **Test hygiene only**: the #5514 capacity-budget regression test is
  de-flaked (#5648) and the browser-control CLI 404-provenance test is made
  deterministic (#5673). No runtime behavior change.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.10"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards
with `disclaude start`. The installation does not modify configuration or
workspace data. Existing 0.6.8/0.6.9 deployments keep their configuration
and workspace data; use the [installation/rollback guide](git-install.md)
to switch releases.
