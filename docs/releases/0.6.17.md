# Disclaude 0.6.17: Codex exec skills honesty, Card 2.0 help/validation, 512MB notebook imports

Release preparation, 2026-11-06. This patch release packages the reviewed
runtime at main `dc0bbe601`, which adds seven scoped changes to the release
baseline: the Codex exec skills-manifest removal (#5683), the executable
next-step candidate card contract (#5693), the table-bearing final Markdown
Card 2.0 rendering (#5695), the cross-channel ownership fail-closed
semantics (#5698), the 512MB chunked `import-file` bridge (#5696), the
offline Card 2.0 help and validation surface (#5703), and the automatic
remote parent-directory creation for Notebook `create` (#5687). Release
preparation changes only version metadata and documentation beyond those
scoped changes. The final source commit, archive, checksums, and fresh
installation results are recorded in the release assets.

## Changes

- Codex `exec`/`resume` no longer fabricate a skills manifest into prompts
  (#5520; #5683). The exec transport has no compliant native registration
  channel — an offline probe of 0.151.0 shows exec only scans
  `<cwd>/.codex/skills` and `$CODEX_HOME/skills`, with no flag, env or
  config key, and plugins require prior installation into `CODEX_HOME` —
  so when Disclaude skill roots exist (always, with the shipped builtins)
  the exec transport now fails fast with an actionable app-server-transport
  diagnostic instead of injecting a self-made skills name/path/description
  list into first-turn, multi-turn and resume inputs. The app-server native
  `skills/extraRoots/set` path from #5546 is unchanged, effective skill
  sets stay identical across transports through the shared
  `codexNativeSkillRoots()` computation, and the only remaining DSH/Pi
  discovery path is the receipt-verified opt-in
  `diagnosticsPluginManifest`.
- Concrete executable next steps are delivered as `send_interactive`
  candidate cards (#5472; #5693). The channel skill now carries an
  "executable next-step candidates" contract: a single option is enough and
  is not padded for symmetry, each button's action prompt carries the full
  instruction bound to the current session/thread-root, the idempotency key
  (`next-step:<origin>`) prevents a second card on retries, nothing runs
  before the click, and no card is sent when there is no beneficial
  follow-up, on plain confirmations, while review feedback is still
  pending, for strict JSON or code-only output, or over card-less channels.
  A service-level regression reproduces the dependency-retirement scenario
  through the real delivery chain: the channel handler builds the actual
  interactive card payload, the click resolves the full action prompt
  chat-scoped, and a same-key retry sends no second card.
- Final Markdown replies that contain tables now render as Feishu Card 2.0
  (#5487; #5695). A final Claude result with a GFM table outside code
  fences and no `## Sources` trailer is converted to a native card by the
  new `final-markdown-card.ts` converter (`column_set` layout): non-
  streaming replies send the card once as an interactive message, and
  streaming replies replace the streaming Card Kit card in place at
  finalize — never a second message. Raw JSON and code-only output stay
  plain text, table-less or `## Sources`-bearing output is unchanged,
  over-budget payloads go through the existing payload budget, and an
  explicit Feishu rejection degrades to text exactly once while unknown
  transport errors propagate without blind retries.
- Cross-channel chat ownership collisions fail closed (#5449; #5698). When
  several channel types are enabled on one instance and a chat id is
  claimed by two channels, delivery is rejected during the conflict instead
  of silently rebinding; `forgetChannelRoutes` cleanup is unified, and an
  unregistered or recovered channel re-binds to the sole healthy owner.
  Text, attachment and card handlers reject ambiguous ownership before
  parsing. A same-process Feishu+WeChat integration regression covers
  inbound ownership, outbound text/attachment routing, capability queries,
  zero delivery on ambiguity, single-channel startup failure not dragging
  healthy channels, and route recovery after unregister.
- The Jupyter `import-file` ceiling rises from 2MB to 512MB with chunked
  upload and verified readback (#5318; #5696). Files above 2MB now go
  through the jupyter-server `LargeFileManager` chunked contract (8MiB
  chunks, `chunk 1..N/-1`) with no manual assembly; the finished upload is
  verified by streaming SHA-256 readback through the `files/` route before
  `imported` is returned. Any failed chunk or checksum mismatch
  best-effort deletes the remote partial and returns a retryable
  diagnostic, and a stale same-name partial with a mismatched size is
  cleaned up and re-uploaded automatically (Disclaude-owned input
  directories only). The small-file path keeps byte-existing/no-overwrite
  semantics, the 512MB ceiling is rejected locally before any remote
  write, and the `import-file` request timeout rises to 300s. Directory
  recursion and object-storage sources stay explicitly out of scope.
- Card 2.0 authoring gets an offline help and validation surface (#5512;
  #5703). `channel card_help` lists and searches components (card, header,
  markdown, column_set, column, collapsible_panel, hr) with field-level
  help and editable native examples; `channel card_check --card|--card-file|-`
  validates fully offline — no chat, no credentials, no message or upload
  side effects. Valid input exits 0 with `{"ok":true}`; invalid input
  returns stable `CARD_*` diagnostic codes with reasons and RFC 6901 JSON
  Pointers plus a help entry point. The bundled `CARD2_SPEC` snapshot
  declares its upstream source and `partial` coverage — unknown components
  answer `NOT_IN_CATALOG` instead of claiming support — and a short
  `card-2` skill plus a sanitized metrics/columns/collapsible fixture let
  agents self-correct from the reported errors.
- `jupyter create --path a/b/c.ipynb` auto-creates missing remote parent
  directories (#5314; #5687). Creation now walks the parent chain level by
  level — GET each directory, and PUT `directory` only on 404 — so a fresh
  remote succeeds directly instead of failing with a generic error.
  Already-existing directories are idempotent, and a rejected creation
  keeps the HTTP status, server body, parent path and a permission hint in
  the error, so the failure names the actionable next step.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.17"
disclaude --version
```

Existing 0.6.16 deployments keep their configuration, registry and
workspace data; stop the running service before upgrading and run
`disclaude start` afterwards. Installation does not touch configuration or
workspace data. Use the [installation/rollback guide](git-install.md) to
switch releases; the prior package remains installed for rollback.

Automated coverage does not replace real-environment acceptance: real
built-in-skill invocation through the Codex app-server transport on a live
account, live Feishu card rendering, a real dual-platform same-instance
deployment, and a real remote Jupyter/Datalayer 100MB-class transfer
remain outside the automated test scope and should be verified in your own
environment.
