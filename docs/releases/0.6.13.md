# Disclaude 0.6.13: codex weekly-quota admission, writer-lock waits, atomic launchd installs

Release preparation, 2026-11-05. This patch release packages the reviewed
runtime at main `0c60edb58f`, carrying five merged changes: #5664 (#5619),
#5677 (#5607), #5684 (#5606), #5682 (#5429) and #5658 (#5652). Release
preparation changes only version metadata and documentation beyond main.

Generated with the hardened release pipeline introduced in 0.6.8 (#5517,
#5522): stale build artifacts are pruned, the runtime is rebuilt from source
with `tsc --build --force`, the build asserts the source tree did not change,
and `release-source.json` records build provenance.

## Changes

- **Weekly-quota admission for codex sessions (#5607; #5677)**: structured
  `RateLimitWindow` readings (`used_percent`, `window_minutes`, `resets_at`)
  are collected from both the exec transport and the app-server
  notifications. When quota-usage progress exceeds the reset-time progress
  of the weekly window, new sessions are blocked with a friendly explanation
  and reset time; already-active sessions keep working and running turns are
  never killed. Defaults to observe mode; thresholds are configurable per
  agent.
- **Writer-lock conflicts become a waitable state (#5429; #5682)**: when a
  codex thread is held by another writer (for example the desktop client),
  the original request is preserved, a visible note explains the occupation,
  and bounded jittered retries (2/4/8/15s, at most five attempts within a
  configurable 60s default budget) resume once the lock clears. `/stop`
  cancels during the wait and the held input is never delivered late.
- **Atomic, idempotent launchd service management (#5619; #5664)**: service
  and Chromium plists are staged to temporary files, validated with
  `plutil -lint`, and atomically renamed; repeated install/start on an
  already-loaded service converges to a no-op or an explicit reload instead
  of an error, concurrent changes share a bounded activation lock, lifecycle
  calls use modern `bootstrap`/`bootout`/`print` semantics, and uninstall
  cleans service-owned state and logs while keeping user profiles unless
  `--purge-profile` is passed.
- **Scheduling skill examples avoid the hour mark (#5606; #5684)**: cron
  examples now use staggered non-hourly minutes, and the guidance asks for
  per-chat staggering when the user did not pin an exact time.
- **Retail Google Chrome in the Chromium container (#5652; #5658)**: the
  image ships a pinned retail Chrome so `navigator.userAgentData.brands`
  matches the User-Agent string. `select_browser_binary()` fails closed when
  the retail binary is missing; there is no Playwright fallback.

The Chromium image changes affect the source-checkout container deployment;
the prebuilt npm package intentionally does not include source-only Docker
assets, while the launchd and scheduling changes are included.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.13"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards with
`disclaude start`. The installation does not modify configuration or
workspace data. Existing 0.6.8–0.6.12 deployments keep their configuration
and workspace data; use the [installation/rollback guide](git-install.md) to
switch releases.

For the Chromium container deployment, rebuild the image to pick up the
retail Chrome layer. For macOS service deployments, `disclaude service`
subcommands now document the new idempotent install, reload and
`--purge-profile` semantics inline.
