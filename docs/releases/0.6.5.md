# Disclaude 0.6.5: 0.6 stability close-out

Release preparation, 2026-10-17. The stable `v0.6.5` tag and GitHub Release
have not been published at preparation time. This document describes
selected content and the existing verification baseline; final package
checks belong in release assets.

## Changes

### One-command issue reporting (#5400)

- Record the last failure of every chat along the cli-main → pool →
  factory injection chain, so a report still exists when the agent itself
  crashed.
- Add a restricted GitHub App issue client (JWT → installation token →
  search or create) and a `github` configuration section whose private key
  is referenced through `$GITHUB_APP_PRIVATE_KEY`, never stored in config.
- `/issue` in Feishu presents a sanitized confirmation card with the
  per-chat last failure and an optional note, files the issue, and replies
  with a link. Failures are marked "not submitted" and keep the report for
  a retry; the failure path never reports success.
- Card callbacks bypass the LLM entirely, so reporting works even while
  the agent is down. Submission is idempotent per diagnostic id, guarded
  by an in-flight lock, and ignores bystander or repeated clicks.

### Provider and model identity

- First-class `modelOverrides` declare gateway model identity: an explicit
  context window and capability flags per advertised model (#5410).
- Transient Codex 429 rate limits retry with bounded backoff, separated
  from exhausted-quota failures that must not retry (#5408).
- A successful answer delivery survives serverRequest/resolved ordering at
  completion instead of being dropped by the completion race (#5404).
- Connectivity-class provider failures are classified separately with an
  egress hint, reflecting their external-network root cause (#5409).

### Chat and Feishu delivery

- Busy notices carry the running turn summary, elapsed time and queue
  depth instead of fixed texts (#5394).
- Oversized mid-turn narration payloads fold into one-line summaries with
  opt-in expansion (#5395).
- Busy-input admission is bounded before turn accounting, so queue
  pressure cannot exhaust the anchor budget (#5399).
- Video delivery stays on the media path without ffmpeg; Feishu media
  rejections no longer masquerade as an unreachable service (#5391).

## Install and configuration

After publication, install the prebuilt GitHub distribution with Node.js 20+, npm 10+ and Git:

```sh
npm install -g "github:hs3180/disclaude#v0.6.5"
disclaude --version
```

Use the [installation/rollback guide](git-install.md), [named-agent guide](../agent-configuration.md),
[secret-source guide](../configuration-secrets.md) and [channel credentials](../channel-credentials.md).
Configure the current schema explicitly; legacy-schema compatibility and an
automatic migration engine are not release requirements. Configuration is not
rewritten by installation. See [optional diagnostics](../skills.md#optional-diagnostics-plugin)
and the [remote Jupyter CLI](../jupyter-service.md) for those opt-in capabilities.

The new `github` section is optional. Until it is configured, `/issue`
reports are unavailable and the flow reports that explicitly instead of
attempting a submission.

## Verified baseline and scope

Main source `50fe57ceb582a75becf9520bec49d2a89fbd350d` passed the six-check
CI suite: forced build, lint and type check, unit tests, package-installation
acceptance, service-image lifecycle and workspace onboarding. The per-PR
suites for #5424/#5425 — including the GitHub App client tests against
nock-verified JWT exchanges and the card-callback tests — were green
locally before merge.

No new real-model acceptance window was run for 0.6.5. The `/issue` flow is
covered by unit tests with faked Feishu and GitHub clients; the deployed
daily service keeps its existing version until deliberately upgraded.
#5402 remains scheduled for 0.7.0 by maintainer decision. npm publication
stays outside the Git release flow: `publish.yml` is manual-only and has
never been run. These boundaries do not turn untested paths into passes.
