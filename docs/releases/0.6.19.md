# Disclaude 0.6.19: prefilled failure-report links and shared model bindings

Release preparation, 2026-11-07. This patch release packages the reviewed
runtime at main `6277ac5c79`, which adds two scoped changes to the release
baseline: prefilled, credential-free GitHub report links attached directly to
error diagnostics with `/feedback` as the single reporting entry (#5428;
#5697), and the cross-harness shared model binding restructure (#5679;
#5681). Release preparation changes only version metadata and documentation
beyond those scoped changes. The final source commit, archive, checksums, and
fresh installation results are recorded in the release assets.

## Changes

- Error diagnostics now carry a prefilled GitHub report link (#5428). The
  link is built entirely locally — no GitHub call, no credentials, no
  network side effects — from the chat's failure record: diagnostic ID,
  failure class, UTC time, Disclaude version, backend/provider and a
  bounded, sanitized detail summary. Markdown-capable channels get a
  clickable link appended to the diagnostic; plain-text channels get a full
  copyable URL; if link generation fails the diagnostic is delivered
  unchanged with an explicit fallback note, so reporting never blocks the
  original error. The public draft deliberately excludes
  chat/session/message/user identifiers, tokens and secrets, message bodies
  and full configuration; a URL above the copyable length limit raises
  explicitly instead of being silently truncated, and parentheses are
  percent-encoded so Markdown links do not break. `/feedback` reports the
  chat's most recent failure through the same draft; on channels without
  confirmation cards it falls back to the prefilled URL as text.
- `/issue` is removed entirely (#5428). `/feedback` is the only reporting
  entry, and `/issue` input now follows the standard unknown-command path.
  The command registry, help text and documentation no longer mention it.
- One shared model binding now works across harnesses (#5679). `llms.<name>`
  holds provider settings plus an optional `defaultModel` that is the wire
  model for every backend sharing the binding; `agents.<name>` selects the
  runtime and the provider, and may use any model that provider serves.
  Claude-only model identity moves to `agents.<name>.claude`:
  - `behavesAs` and `modelOverrides` (previously under `llms.<name>`);
  - a new three-tier `models` mapping (`opus`/`sonnet`/`haiku`) for the
    Claude Code multi-agent slots — each tier falls back to the provider
    `defaultModel`, so configuring a single model points all three tiers at
    it;
  - Claude-native environment such as
    `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`.
  `llms.<name>.reasoningEffort` becomes a provider-level default that
  runtimes which cannot apply an effort ignore, instead of a harness gate.
  A binding shared by Claude and another backend (DSH/Pi) whose
  `defaultModel` is a bare Claude alias (`opus|sonnet|haiku|fable|default`)
  now fails at configuration load with a fix hint — Claude resolves such
  aliases internally while the other backends would put the literal string
  on the wire — instead of silently sending different models per harness.
  Legacy placements are rejected at load with migration messages:
  `llms.<name>.model` (renamed to `defaultModel`), `llms.<name>.behavesAs`
  and `llms.<name>.modelOverrides` (moved to `agents.<name>.claude`), and
  `ANTHROPIC_DEFAULT_*_MODEL` keys under `llms.<name>.env` (moved to
  `agents.<name>.claude.models` or `agents.<name>.claude.env`). Tests assert
  the model ID actually handed to the Claude and DSH providers, not just
  YAML parsing, so a shared binding cannot silently drift apart again.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.19"
disclaude --version
```

**Upgrade note (configuration migration).** Deployments using the old
`llms.<name>.model`, `llms.<name>.behavesAs` / `modelOverrides`, or
`ANTHROPIC_DEFAULT_*_MODEL` entries under `llms.<name>.env` must move them
to the new locations above before this release loads the configuration;
the loader reports each legacy key with its target location. Shared
bindings that pin a bare Claude alias as the default model must pin the
provider wire model in `llms.<name>.defaultModel` and, when Claude needs the
alias slot, set `agents.<name>.claude.behavesAs` to a full Claude model ID.
See `docs/agent-configuration.md` for the full reference and the committed
`disclaude.config.example.yaml` for annotated examples.

Existing 0.6.18 deployments keep their registry and workspace data; stop
the running service before upgrading and run `disclaude start` afterwards.
Installation does not touch configuration or workspace data. Use the
[installation/rollback guide](git-install.md) to switch releases; the prior
package remains installed for rollback.

Automated coverage does not replace real-environment acceptance: a real
failure opening the prefilled link in a browser without any local GitHub
credentials, and a live Claude+DSH deployment sharing one binding through a
gateway route, remain outside the automated test scope (both chains are
covered against mocks) and should be verified in your own environment.
