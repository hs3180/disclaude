# disclaude 0.5.1 Release Notes

状态：待发布。GitHub tag 直装是 [#4922](https://github.com/hs3180/disclaude/issues/4922) 明确的发布阻断项；
本说明的提交不代表版本已经发布。最终安装验收见 [发布候选记录](0.5.1/release-candidate.md)。

## 本次更新

- 完全移除 Primary Node/Worker 角色（#4924）：统一使用 `disclaude start`，内部包为 `@disclaude/service`，不保留旧命令/类型别名。升级前请阅读 [服务迁移说明](../migrations/0.5.1-service.md)，避免旧、新服务同时运行；配置、workspace、会话和调度数据保留。
- 修复 Claude 后端把 YAML-only Anthropic/GLM 凭据误判为不可用的问题，启动失败不再静默切换后端。
- 支持未来带后缀的 Codex 模型名称；优先读取用户级配置。
- 未标记 default 的 presets 按声明顺序选择；空集合返回明确错误，纯数字名称需改为 `agent-1` 等形式。
- 移除旧 TaskTracker/DialogueMessageTracker，构建及打包前清理失去源码对应项的旧产物。
- 修复测试对开发者本机配置的依赖，补充 Channel CLI `--parent` 使用指引。
- 自动压缩优先采用 `agent.autoCompactWindow`；未配置时查询当前模型 API，使用 context 上限的 80%。不再注入固定 100k 兜底值。详见 [自动压缩说明](../auto-compaction.md)。

## 升级注意与已知限制

- 原先依赖固定 100k 兜底的用户应检查模型 API 是否提供 context 上限。DeepSeek 当前只返回模型 ID 等信息，需显式设置 `agent.autoCompactWindow`；查询失败会告警，SDK 自身行为保持不变。
- `autoCompactWindow: 0` 现在明确关闭 SDK 自动压缩；显式阈值同样适用于原生 Claude 模型。
- 自动压缩不保证接收任意长度的单次输入；超大输入实测仍可能先报 `Prompt is too long`，之后才压缩恢复。
- 飞书真实验收覆盖指定普通群中的文本、附件及文本 parent 回复；P2P、话题群与卡片回复不在本次实测覆盖范围。

## 从 GitHub 安装

使用经过远程安装验收的预构建发行标签（正式标签尚未创建）：

```bash
npm install -g "github:hs3180/disclaude#v0.5.1"
disclaude --version
disclaude start --help
```

- 安装来源是 GitHub，不是 npm registry；根包可以保留 `private: true`。
- 使用 Git、Node.js 20+、npm 10+；预构建标签不要求用户安装 TypeScript 或 Husky。
- 开发者使用 `npm run hooks:install` 显式初始化 hooks，用户安装不再运行 Husky。
- 标签指向生成的发行提交，源码 SHA 与内容指纹记录在 `release-source.json`；main 保留开发结构，不作为全局安装入口。
- Release `.tgz` 可作补充分发，但不能替代 tag 直装发布验收。
- 新安装的示例配置位于 `$(npm root -g)/disclaude/disclaude.config.example.yaml`。
  将其复制到 `~/.disclaude/disclaude.config.yaml`，配置后端、渠道及 workspace，
  创建相应 workspace 目录，再执行 `disclaude start`。
- 升级前备份现有配置和 workspace；不要用示例配置覆盖已有配置。

也可以使用 [README 中的源码安装方式](../../README.md#option-b-install-the-github-source-distribution)。

## 发布步骤

按 [Git 发行流程](git-install.md) 从已合并源码生成发行候选，完成远程 SHA
安装、Linux/macOS 和 Node/npm 验收，并在明确发布授权后对已验收发行提交创建 `v0.5.1` 标签。
维护者先将 [安装工作流模板](package-install.workflow.yml) 安装为
`.github/workflows/package-install.yml`（提交用 GitHub App 尚无 workflows 写权限）。
工作流应在源码 PR 上安装固定远程发行 SHA；不要在生成的发行标签上运行开发构建。
可选 `.tgz` 从同一个已验收发行目录打包，上传为 GitHub Release 资产。
不要从长期使用的开发目录打包，也不要重新构建替换已验收的发行内容。
发布前复核上述 GitHub tag 安装命令和全部 CLI 入口；不能仅凭 `.tgz` 验收宣称发布完成。
根包保留 private，本版本通过 GitHub 分发，不执行 npm publish。
