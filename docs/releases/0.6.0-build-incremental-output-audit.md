# 0.6.0 构建增量输出审计

日期：2026-09-21（Asia/Shanghai）  
基线：`origin/main` / `d6be9e5e`

## 发现

在复用过的 Git worktree 中，如果 TypeScript 的 `tsconfig.tsbuildinfo` 仍在、对应包的 `dist/` 已被清理，普通的 `npm test` 会让 `tsc -b` 误认为包已经完成构建，不重新生成入口文件。随后 Vitest 无法解析 `@disclaude/core` 的 `dist/index.js`，246 个测试文件在导入阶段失败。

## 可复现边界

受影响状态同时满足：

- `packages/*/tsconfig.tsbuildinfo` 存在；
- 对应包的 `dist/` 不存在；
- `npm test` 先运行 `scripts/prune-build-artifacts.mjs`，再运行普通 `tsc -b`。

本轮在 #5149 的独立修复 worktree 中观察到：`npm ci --ignore-scripts --no-audit --no-fund` 后，`npm test` 触发 246 个文件的 `@disclaude/core` 入口解析失败；检查确认 `dist/` 缺失而 `tsconfig.tsbuildinfo` 存在。执行 `npx tsc -b --force` 重新生成产物后，同一源码通过完整回归：248 个测试文件、4901 个测试。

## 影响与边界

这是重复使用本地 worktree 或清理过构建产物后的可复现构建问题，不是业务测试断言失败；全新 checkout 通常没有旧的 build info，因此不能用现有 CI 绿灯排除该问题。`scripts/prune-build-artifacts.mjs` 只清理过期输出，不处理“输出目录缺失但增量状态仍存在”的矛盾。

本 discovery PR 只记录证据。对应修复应在独立的 fix PR 中，让构建入口在输出目录缺失时失效旧的增量状态，再由 TypeScript 重新生成包入口；不改变运行时功能或发布入口。
