# Disclaude 0.6.31: Claude model tiers declared through `claude.modelMapping`

Release preparation, 2026-11-27. This patch release packages the reviewed
runtime at main `fc41ccebe`. One merged change ships since 0.6.30: the Claude
agent's model capability tiers are declared only through the three-tier
`agents.<name>.claude.modelMapping`, compiled at configuration time into the
parameter mapping passed to Claude Code, and the `behavesAs` /
`modelOverrides` configuration keys are removed (#5422; #5725). Release
preparation changes only version metadata and documentation beyond that
reviewed change.

## Changes

- Declare the Claude model capability tiers through
  `agents.<name>.claude.modelMapping` and retire `behavesAs` and
  `modelOverrides` (#5422; #5725). Config always compiles three tiers: every
  tier alias key (`opus`, `sonnet`, `haiku`) maps to the declared
  `modelMapping.<tier>` value (a full Claude model ID is passed through
  unchanged) and an omitted tier falls back to the provider's
  `llms.<name>.defaultModel`. Claude Code resolves each tier alias against
  its current catalog, so a gateway or provider-specific model ID bound to a
  tier keeps its capability binding across Claude Code upgrades instead of
  the override key silently going stale. The repository's types, SDK options
  and runtime properties are named `modelMapping` throughout
  (`ClaudeModelMapping`, `AgentQueryOptions.modelMapping`, the
  `claude_model_mapping` event, `MODEL_MAPPING_MIN_VERSION` /
  `lacksModelMapping()`); the options adapter is the single point that
  translates `options.modelMapping` into Claude Code's native
  `settings.modelOverrides` key, and an empty mapping is not written.
  `assumedContextWindow()` moves to `sdk/providers/claude/model-alias.ts`
  next to the new `isFullClaudeModelId()`. The example configuration,
  `docs/agent-configuration.md` and `docs/configuration-secrets.md` document
  the three-tier declaration as the only configuration source.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.31"
disclaude --version
```

**Upgrade note.** Deployments that declare `agents.<name>.claude.behavesAs`,
`agents.<name>.claude.modelOverrides` or `llms.<name>.behavesAs` must migrate
their configuration before starting 0.6.31: express the capability slots as
the three tiers of `agents.<name>.claude.modelMapping` (`opus`, `sonnet`,
`haiku`, each a model the provider serves), and leave tiers you do not need
to the provider `defaultModel`; each stale key is now an explicit
configuration error that points at `modelMapping`. The tier alias key surface
requires Claude Code >= 2.1.200; agent startup fails with a clear error when
the bundled CLI is older. Configurations without those keys need no change.
Stop the running service before upgrading and run `disclaude start`
afterwards; installation does not touch configuration, credentials, or
workspace data. Use the [installation/rollback guide](git-install.md) to
switch releases; the prior package remains installed for rollback.
