# Disclaude 0.6.7: WeChat relogin hardening and channel fixes

Release preparation, 2026-10-23. This patch release packages the reviewed
runtime at main `dcd19b29`, which adds four late-filed bugs to the release
scope (#5480, #5489, #5504, #5505). Release preparation changes only version
metadata and documentation beyond those scoped fixes. The final source
commit, archive, checksums, and fresh installation results are recorded in
the release assets.

## Changes

- Harden the WeChat re-login path end to end: probe the old login before
  reporting a rolled-back re-login (#5500), require remote poll confirmation
  before listener health is declared (#5501), and report login stages while
  verifying fresh credentials before declaring registration (#5502, carrying
  the relogin-isolation regressions, installed-package rollback lifecycle and
  the SIGTERM fix from #5503).
- Explain a scanned identity change during a forced WeChat re-login instead
  of failing without guidance for safely adopting the new bot identity
  (#5480).
- Keep used Feishu private-input cards on their real terminal status so a
  successful submission no longer shows as expired (#5489).
- Carry the real failure through a codex `turn/start` ACK timeout: the
  structured timeout reaches settlement exactly once with its method, stage
  and submission uncertainty, restart classification uses the real error,
  and the timed-out request is never replayed (#5505).
- Drop self-sent user-identity echoes before they re-enter the conversation:
  a bounded self-sent registry, a `self_sent` filter reason ahead of the
  dedup claim, and a Bearer-authenticated `POST /api/self-sent/:messageId`
  registration route for session-side senders (#5504).
- Keep `disclaude start` responsive to SIGTERM even when a held long poll
  swallows both its listener abort and its own deadline: API waits race their
  controller's abort signal and listener shutdown stops waiting after a five
  second grace.
- Keep safe rejection detail on WeChat API errors — endpoint path, HTTP status
  and a diagnostic id — instead of a bare numeric code, and retry the listener
  lock when its owner releases it mid-acquisition.
- Degrade unsupported codex async questions to plain text, classify
  `max_output_tokens` turn failures with a progress-aware receipt, and continue
  in the same thread after capacity failures instead of dropping the turn.
- Adapt GFM tables in Feishu auto citation cards, and keep message-topic
  identity for p2p and group inputs.
- Re-discover CDP after browser `--reload` while migrating the runtime
  identity, and validate replaced `service.lock` ownership by inode.
- Assert the Node.js security baseline at service image build time
  (2026-10-21 release train) and bump the Chromium base image default to
  `v1.64.1-noble` (Chromium 156.0.8078.4, built 2026-10-14).
- Pre-link the canonical config slot in the service image so official mounts
  no longer trip the legacy-location warning, and parse
  `channels.feishu` credentials with the loader's own primitives.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.7"
disclaude --version
disclaude wechat login
disclaude wechat status --check
```

Existing 0.6.6 deployments keep their configuration, WeChat registry, and
workspace data. Use the [installation/rollback
guide](git-install.md) to switch releases; the prior package remains
installed for rollback. The WeChat channel guide
([../wechat-channel.md](../wechat-channel.md)) covers the registry directory,
login commands, coexistence configuration, and recovery behavior.

The personal iLink bot scope is unchanged: MP4 native video output, 4000
UTF-8 bytes per text part and 20 MiB per file remain the local limits; input
video/voice decoding, WeChat cards/buttons, and streaming edits stay outside
the supported scope.
