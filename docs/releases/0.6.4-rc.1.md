### Configuration and upgrade recorded at that source

Back up the actual service configuration and workspace before an upgrade.
Agents now bind to named entries in `llms`; see the
[configuration guide](../agent-configuration.md) and
[example configuration](../../disclaude.config.example.yaml).
Anthropic-compatible alternative models use `llms.<name>.api.protocol:
anthropic`, their endpoint and a host-side credential reference. Model aliases
belong to that LLM's `env`. Target credentials take precedence when switching
presets. Native Codex uses its CLI account and needs no API block.

The daily/candidate default is `gpt-6-luna`, with reasoning effort `max` and
LLM session capacity 3 in the example. Historical source configurations and
explicitly overridden acceptance cases retain their recorded models.

Jupyter commands use the configured remote deployment from the host Node CLI.
Python, scientific packages and kernels are managed by that remote deployment.
`jupyter interrupt` targets an existing kernel; HTTP 204 acknowledges the
request and does not prove execution ended. `jupyter stop` retains its
original-run cancellation semantics.

## Candidate installation and rollback

After generating the committed-source distribution and verifying its receipt,
install the archive into an isolated prefix for review:

```sh
npm install -g --prefix /path/to/isolated-prefix /path/to/disclaude-0.6.4-rc.1.tgz
/path/to/isolated-prefix/bin/disclaude --version
```

Keep the working package, configuration backup and workspace. A service switch
must stop the old process before starting the candidate so that two bot
connections cannot compete. Restore the working package and its compatible
configuration together if acceptance fails; verify health and channel
connection after restoration. See the
[installation and rollback guide](git-install.md).
