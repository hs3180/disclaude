# Research collection time and literal metadata writes

Earlier real Luna history restoration displayed a timestamp generated when
updating the overview, rather than when body/comment collection completed.
Unescaped shell backticks also removed `ß`/`ss` from a new scope summary; that
run disclosed and repaired the error, and its failed artifact remains retained.

Implementation `d4329e80` and routing correction `f907dd19` add:

- A read-only live collector that fetches the full body, all comment pages and
  all reply pages through argument arrays, validates them with the existing
  adapter, then records collection start/completion times and original responses.
- Checkpoint retention of that collection interval. Failed reads do not produce
  complete snapshots; untimed legacy snapshots clear the time instead of
  carrying an unrelated earlier time forward.
- A JSON-input writer for one targeted replacement or append, using an argument
  array without a shell or automatic retry. Unicode, backticks and newlines are
  passed literally. Unknown outcomes still require read-back before retry.

The overview identifies the collection and revision that informed its update.
The final chat gives the final confirmed checkpoint's last synchronization time.
This avoids repeatedly rewriting a document to chase timestamps generated by
its own read-back. It is sequential checkpoint collection, not atomic remote
reads, continuous sync or remote transaction locking. Manually supplied time
metadata remains an attestation; the live collector is the verified source.
