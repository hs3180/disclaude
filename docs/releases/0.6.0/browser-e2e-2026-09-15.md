# Browser product E2E report — 2026-09-15

## Result and scope

Tested code: `8cbd67a9736a51fe124073b8b9d5504c1a591372` (PR #5017).
The actual `disclaude start` → managed Chromium → IPC `browser-use` caller path
passed on macOS/arm64 and Linux/amd64. This report covers all assertions in
`tests/e2e/browser-service.test.ts`, including negative cases. It is not a claim
that every browser release criterion or 0.6.0 delivery is complete.

The test uses real processes, a real browser and a real page. It does not mock the
coordinator, worker, socket or browser. It disables Feishu and uses an offline model
placeholder: callers run explicit Python operations, not model-generated actions.

## Scenario matrix

Every row below passed in both product E2E executions. The test repeats the full
startup/operation/shutdown sequence twice with the same profile directory.

| User or failure scenario | Actual assertion |
| --- | --- |
| Start the service | Launch `bin/disclaude.js start` as a child process with a private config/workspace; wait for product API readiness; `disclaude browser status` reports `idle` |
| Execute a browser operation | Invoke the installed managed `browser-use` entry; navigate a real data page, find its input and fill it |
| Share browser state | Concurrent callers use the same page; a later caller observes the value written by the first |
| Queue callers | Both concurrent operations complete through IPC. The second may observe the before/after value because arrival order is not assumed; the final observation must see `handoff` |
| Remove stale direct-CDP settings | Agent environment excludes supplied stale `BU_CDP_URL` and `BU_CDP_WS` values |
| Missing IPC fails closed | Invoke with a nonexistent socket and an injected direct-CDP URL; expect connection failure and absence of the Python side-effect marker |
| Failure does not break healthy IPC | A subsequent caller on the correct socket still reads the retained page value |
| Interrupted caller is reclaimed | Start a worker, wait for its marker, queue a successor, kill the calling process; expect interruption, successful successor and absence of the abandoned operation's marker |
| Graceful shutdown releases ownership | SIGTERM the product service; expect exit 0, removed socket and lock, closed CDP endpoint and failing browser-status command |
| Preserve profile across restart | A profile marker survives shutdown; the next product startup uses the same retained directory and completes the operations again |

The interrupted-caller check is not equivalent to killing the coordinator itself.
The profile marker proves directory retention, not successful website login recovery.
Concurrent callers exercise serialization and shared state, not a hostile-code
security boundary or a multi-agent research workflow.

## Failure investigated during this PR

The earlier native Linux attempt downloaded Playwright Chromium and failed during
browser startup. Evidence remains in runs
[34976714803](https://github.com/hs3180/disclaude/actions/runs/34976714803),
[34977154752](https://github.com/hs3180/disclaude/actions/runs/34977154752) and
[34977512944](https://github.com/hs3180/disclaude/actions/runs/34977512944).
The process exited by signal with native crash diagnostics. The exact native crash
cause has not been established; this report does not attribute it to a confirmed
sandbox/AppArmor issue.

The runtime now captures bounded startup diagnostics and detects signal exits.
The outer E2E wait lets the service's own 45-second startup deadline report failure.
Using the runner's packaged Chrome passed the same product test. No host security
settings were disabled and no non-root `--no-sandbox` workaround was introduced.
This result does not validate the failed downloaded binary.

## Reproduction

Use a clean worktree with dependencies and a supported installed Chromium/Chrome.
Install the Python dependencies shown by the workflow. Supply absolute paths:

```sh
npm ci
npm run build
DISCLAUDE_E2E_CHROMIUM=/absolute/path/to/chrome \
DISCLAUDE_E2E_BROWSER_PYTHON=/absolute/path/to/python3 \
  npx vitest run tests/e2e/browser-service.test.ts
```

The test creates and cleans its own temporary workspace/profile; it does not attach
to the user's daily browser. Without both explicit environment variables, the
E2E is skipped; a skip is not an acceptance pass.

## Opt-in real model/tool extension

The subsequent extension of the same product E2E passed on the macOS environment
above at 22:21 CST: one E2E, 23.02 seconds test time (23.28 seconds total).
It used the installed dsh SDK backend and the configured `deepseek-flash` model.
The test requires `DISCLAUDE_E2E_BROWSER_MODEL` and `DEEPSEEK_API_KEY`; the
credential-free Linux job does not exercise this extension.

After opening the shared page through the product launcher, the real model receives
a task to call `browser-use` through its shell tool and change the input to a unique
marker. Assertions require actual tool-use/tool-result events, a completed terminal
result, and a separate IPC caller reading the resulting marker from the browser.
The rest of the shutdown/profile-retention/restart assertions still run afterward.
The dsh process uses a temporary private home and receives the agent-visible IPC
environment. Model API credentials are neither committed nor included in this report.

This covers one actual dsh model executor handing page state to an independent
Python caller. It does not prove all backends, two-model collaboration, real website
login flows, Feishu/browser UX or model quality. The first extension attempt failed
because its temporary DSH_HOME had not been created; creating that test directory
fixed the setup failure without changing production behavior.

To enable this extra path, set `DISCLAUDE_E2E_BROWSER_MODEL` to an available model
and provide the existing dsh API credentials in addition to the two browser paths
in the reproduction command. This makes real model API calls.

## Follow-up: supervised broker crash cleanup

The follow-up based on merged `01c1596c` adds an active-task broker SIGKILL case
to the same product E2E. On 2026-09-15 at 23:58 CST, macOS/arm64 with Node 24.8.0
passed in 16.23 seconds (16.52 seconds including test setup). The original Linux
results above predate this increment; its Linux CI result is still pending.

After ordinary shared-page handoff and caller interruption, the test starts a
real Python operation that spawns another Python process, waits for its PID file,
and kills the broker identified by its ownership file. It verifies that the
request fails, managed Chromium's CDP port closes, the spawned process exits,
the deferred side effect is absent, and the owned socket/lock disappear. It then
explicitly restarts Disclaude using the preserved profile and repeats the normal
product use case. No model call or live Feishu message is involved.

A core process regression first reproduced the orphaned descendant, then passed
with group cleanup. Twelve lifecycle/environment tests pass, including preserving
IPC files with a different instance identity. Full build/lint and JavaScript
syntax checks pass. Recovery still requires a live owning supervisor; standalone
broker death, legacy/foreign locks, simultaneous supervisor/broker loss and OS
service/profile migration are outside this added acceptance.
