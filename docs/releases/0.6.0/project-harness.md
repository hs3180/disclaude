# 0.6.0 Agentic Research 交付约定

本文记录已确认的产品边界与验收要求，不代表 0.6.0 已交付，也不代表当前 main 已接通全部入口。需求来源是 [#4753：工作空间与证据交互](https://github.com/hs3180/disclaude/issues/4753)、[#4754：研究推进、控制与恢复](https://github.com/hs3180/disclaude/issues/4754) 及 [#5021 的拆分与评审](https://github.com/hs3180/disclaude/pull/5021)。实现状态、评审与实际验收证据分别记录，不能互相替代。

2026-09-17 用户范围纠正：**可复用的持续执行能力不是 0.6.0 交付目标。** 本文仅约束 Research 自身的用户体验，不要求交付通用任务框架、独立持久任务管理器或以非研究长任务证明复用性。已有执行能力可以按需使用，其通用化不构成发行门槛。

2026-09-18 用户设计纠正：**TASK.md 相关功能不在 disclaude 设计计划内，直接移除。** 不引入约定任务目录、feedback.json 账本、文件索引或其校验脚本，也不以替换文件名或另一套任务管理器延续该设计。现有用户文件保留为普通文件，不自动迁移或删除。

## 用户如何开展工作

用户在现有项目内通过普通聊天提出研究目标。`/project` 提供工作目录绑定，不扫描或展示任务文件，不增加 `/research` 命令、研究模式或启用开关。`/project use <目录>`、`/project info` 和 `/project reset` 管理会话工作目录；切换会话目录不迁移已建立任务的目录或文件。

任务界面应直接显示当前进展、阻塞、未处理反馈、工作与证据、成果和可用操作。用户离开后能从研究文档及聊天中的稳定链接重返工作，无需翻聊天记录或手动执行 CLI。来源事实、推断和未知必须区分，结论能追溯出处及限制。用户可以修改范围、提出反例、停止某个方向、暂停或取消整个任务，并从已完成的发现继续新任务。

Research 需要保留上下文、获取资料、记录证据与产物，并支持人工反馈、恢复和研究任务隔离。Agent 根据问题与证据选择执行过程；简单核验与开放调查可以采用不同方法。不能把固定的 `plan → investigate → synthesize` 流程、Skill、提示词或报告模板当作完整产品体验。预算、超时、访问权限和用户控制仍是执行边界。

飞书文档与飞书聊天是研究的主要界面：文档持续呈现进展、证据、成果与修订，聊天支持发起、讨论、调整方向和自然语言控制，并提供稳定文档链接。本地文件用于内部接续，不能以本地路径消息代替用户可访问的研究文档。

卡片仅按需获取特定反馈，例如澄清范围、选择方案或确认具体操作；问题须有相关上下文，回答须关联原工作。研究后可以根据发现与未解决证据提出可选追问，在聊天中呈现，或用卡片让用户选择具体的后续调查。追问不妨碍阅读成果或自由对话，未选择不自动启动新工作。卡片不作为项目首页、证据浏览器、必经表单或常驻控制面板，也不因每轮结束就发送无关的通用菜单。

## 状态和恢复约束

| 场景 | 用户可观察的结果 |
| --- | --- |
| 暂停执行 | 当前回合按契约收尾并保存检查点；显示暂停状态，不擅自启动下一轮。 |
| 提交反馈 | 显示待处理意见及后续采纳、拒绝或澄清原因；采纳应关联实际工作、证据或结论变化。暂停或中断期间的意见不自动恢复执行。 |
| 停止一个方向 | 后续不再推进该方向，其余有效工作按调整后的计划继续；不接纳已失效的在途结果。 |
| 取消整个任务 | 保留此前成果，明确在途结果的处理；取消中不提前提供终态续任务操作。 |
| 服务中断 | 重返同一任务与固定目录，保留已提交检查点、来源及反馈；明确恢复入口，不能用创建替代任务冒充恢复。 |
| 从成果继续 | 新任务与原成果保持可追溯关系，原记录不被覆盖。 |
| 多任务或多会话 | 内容、身份、反馈、目录和控制不串用；一个任务的暂停或失败不改变另一个任务的成果。 |

持久项目任务的显式恢复不等于普通会话请求的自动续办。后者由 [#5075](https://github.com/hs3180/disclaude/issues/5075) 单独定义，不能以一个受控项目任务的恢复结果宣称已经满足。

## 关联飞书文档

关联文档后，在执行检查点和恢复执行前读取最新正文与评论。界面显示最后同步时间、待处理反馈和同步失败；检查点同步不能标成实时同步。读取失败保留已有进度，并暂缓依赖最新意见的执行，不能声称已采纳尚未读到的内容。

用户改正文或加评论应能实质影响后续工作。回写前读取最新内容，以增量方式保留用户修改；冲突无法合并时保留双方内容并展示冲突。重复事件、重试以及结果不确定的写入须可追踪，不能盲目重放外部副作用。成果追加是显式操作，不能以反馈回执代替成果完成。

## 兼容与迁移

保留旧任务身份、工作目录、来源与成果链接、卡片回调以及用户和会话访问边界。旧存储配置只作为兼容输入，不作为启用研究模式的条件。内部遗留的 `research` 回调字段或目录名不构成产品模式。不得静默搬文件、删除用户数据，或以重建任务代替迁移。

## 验收所需证据

以下是交付门槛，不是已通过清单。每项记录实际候选提交、部署环境、操作路径、期望与观察结果、失败记录及清理结果。

1. 真实飞书自然语言发起任务，查看工作与证据；多轮修改范围并提出反例，确认实际工作和结论随反馈变化，且能追溯来源和意见处理过程。
2. 简单核验与开放调查采用合适且可不同的执行过程，不强制固定研究阶段；无需非研究长任务或通用持续执行框架验收。
3. 原生界面执行暂停、单方向停止、取消、离开重返与从成果继续，核验保留内容、在途结果处理和可用操作。
4. 观察真实在途子进程后中断服务，核验进程回收、重启、原任务重返与恢复完成；单纯重开存储不证明进程崩溃恢复。
5. 中断后修改研究文档正文并新增评论；恢复后采用最新内容，保留已完成证据及用户修改，并从实际飞书文档与聊天核对结果与来源；主路径无需进入卡片任务面板。
6. 实际并行执行的多个任务不串内容或操作。只观察多个任务的 `running` 状态，不足以证明多个模型进程并发隔离。
7. 并发编辑、重复事件、权限不足、文档同步失败及通知失败具有可复现路径、可理解状态和恢复结果，成果及用户修改保留。
8. 旧记录和已发卡片仍可访问，权限边界正确；完成最终集成版本的安装、部署、升级与恢复验证。

E2E 客户端应是访问测试部署的外部独立进程，报告区分准备完成、局部通过、完整通过和清理失败。直接导入服务内部 controller 或捕获卡片传输的测试不能替代部署验收与真实飞书点击。复用生产机器人验收时，保留原配置和 workspace，避免竞争连接，每轮结束恢复日常服务并独立核验健康；清理本轮创建的临时文件、文档及运行资源，保留必要的脱敏证据。

CI、单元测试、受控价格样例和历史版本演示只能证明各自覆盖范围；不能据此勾选开放调查或完整 UX 验收。PR 按独立范围直接基于 main 提交，由维护者审阅和合并。完整交付以全部适用门槛和最终集成版本的证据为准。
