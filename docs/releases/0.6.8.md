# Disclaude 0.6.8: maintenance batch — channel reliability, agent session fixes, hardened release build

Release preparation, 2026-11-04. This patch release packages the reviewed
runtime at main `8f9dca52a37d`, which carries 77 commits beyond the 0.6.7
source: eighteen fixes reviewed through the maintenance pilot (#5625, #5626,
#5627, #5628, #5629, #5632, #5634, #5635, #5636, #5637, #5638, #5639, #5641,
#5642, #5643, #5644, #5645, #5646) plus the maintainer's goal, board and
coordination line. Release preparation changes only version metadata and
documentation beyond main.

This is the first distribution generated with the hardened release pipeline
(#5517, #5522): stale build artifacts are pruned, the runtime is rebuilt from
source with `tsc --build --force`, the build asserts the source tree did not
change, and `release-source.json` records build provenance (typescript
version and runtime fingerprint). Fixes that 0.6.7 declared but did not
actually ship because of stale dist output are present in this build.

## Changes

- **WeChat registry locks** no longer take a host down: a corrupt lock (for
  example the zero-byte file left behind when a full disk interrupts a
  write) is quarantined automatically and the lock rebuilt, so the service
  recovers instead of crash-looping under launchd (#5513; #5525, #5523,
  #5577, #5632). A conservative manual `lock-recover` remains available.
- **WeChat media and delivery diagnostics**: CDN upload failures now surface
  underlying cause codes with structured, sanitized diagnostics (#5516),
  failed inbound images stay recoverable through a durable asynchronous
  inbox instead of being acknowledged and dropped (#5518), and channel-cli
  JSON failures carry structured delivery diagnostics with two-layer
  diagnostic ids (#5616).
- **WeChat conversation identity** binds to a stable peer identifier
  (persisted atomically, scoped to the operator identity), so the periodic
  iLink re-registration continues the original chatId — session history,
  context and schedules survive (#5600).
- **WeChat onboarding and presence**: new peers get a one-time welcome once
  a valid reply context exists (#5469), and the typing indicator is retained
  through task and delivery settlement so long tasks no longer look dead
  (#5471).
- **Feishu delivery reliability**: uploads get a chain-aware deadline with
  per-stage timings and idempotency keys instead of one ambiguous 30-second
  REST timeout (#5630); a consumed private-input card resumes the waiting
  session automatically and reports its real terminal status (#5411); an
  async question card that fails to deliver no longer rewrites the whole
  turn as failed — delivered outcomes stand (#5526, #5430); forwarded card
  content is preserved in thread context instead of degrading to a
  placeholder (#5433).
- **Agent session lifecycle**: a tripped reply circuit recovers through a
  bounded half-open probe and backfills skipped replies (#5470); new tasks
  sent to a busy main conversation get their own execution boundary instead
  of being steered into the running turn (#5464); capacity recovery no
  longer charges healthy work against the recovery budget (#5514); late
  reconnects cannot revive disposed queries (#5572); SDK subprocesses get
  default foreground Bash timeouts so waiting commands cannot wedge a
  session forever (#5515).
- **Startup honesty**: Feishu channels report available only after DNS
  resolution and a real websocket connection (#5519), and browser status
  explains where the CDP endpoint is and why a runtime is unavailable, with
  a classified remedy (#5601).
- **Goal / board / coordination** (maintainer line): single-entry `/goal`
  surface with native execution, versioned goal persistence, durable task
  claims with projection-checked admission, review records through lark-cli,
  receipt inboxes, background task ownership in the default service, Feishu
  task feedback cards, and a session history query service
  (`disclaude history query`, `GET /api/history/query`) as the primary agent
  entry (#5538–#5624 line; #5611, #5629).
- **launchd service lifecycle** is now verifiable: `generatePlist()` derives
  a production-faithful plist from `.disclaude` configuration and the
  `disclaude service` command family manages it, with `--dry-run` support
  (#5619).

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.8"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards
with `disclaude start`. The installation does not modify configuration or
workspace data. Existing 0.6.7 deployments keep their configuration, WeChat
registry, and workspace data; use the [installation/rollback
guide](git-install.md) to switch releases. The WeChat channel guide
([../wechat-channel.md](../wechat-channel.md)) covers the registry
directory, login commands, coexistence configuration, and recovery
behavior — including the new automatic corrupt-lock quarantine.

The personal iLink bot scope is unchanged: MP4 native video output, 4000
UTF-8 bytes per text part and 20 MiB per file remain the local limits;
input video/voice decoding, WeChat cards/buttons, and streaming edits stay
outside the supported scope.
