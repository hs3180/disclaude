# Disclaude 0.6.12: Chromium software WebGL and persistent browser sessions

Release preparation, 2026-11-05. This patch release packages the reviewed
runtime at main `b19efbc4810a`, carrying the Chromium container improvements
from #5657 (#5653). Release preparation changes only version metadata and
documentation beyond main.

Generated with the hardened release pipeline introduced in 0.6.8 (#5517,
#5522): stale build artifacts are pruned, the runtime is rebuilt from source
with `tsc --build --force`, the build asserts the source tree did not change,
and `release-source.json` records build provenance.

## Changes

- **Software WebGL without a GPU**: the headed Chromium launcher now enables
  SwiftShader through the ANGLE Vulkan backend (`--enable-unsafe-swiftshader
  --use-gl=angle --use-angle=vulkan`). It deliberately does not use the `gles`
  backend, which blanks WebGL on Xvfb (#5653; #5657).
- **Session cookies survive container recreation**: Chromium starts with
  `--restore-last-session`; when the profile volume is retained, session-level
  cookies and login state survive a full container rebuild and recreate.
  Restoring the previous session also reopens its tabs (#5653; #5657).
- **Browser UI language matches Accept-Language**: `--lang` now uses the first
  segment of `CHROMIUM_ACCEPT_LANG`, rather than leaving the UI at en-US while
  only the HTTP language preference changes (#5653; #5657).
- **Configurable persistent profile storage**: the image declares
  `/data/chrome-profile` as a volume. Compose keeps the managed
  `chromium_profile` volume by default, while `CHROMIUM_PROFILE_VOLUME` can name
  an absolute host directory to bind-mount instead (#5653; #5657).

These changes affect the source-checkout Chromium container deployment. The
prebuilt npm package intentionally does not include source-only Docker assets.

## Install and use

Requires Node.js 20+, npm 10+, and Git. After the release is published:

```sh
npm install -g "github:hs3180/disclaude#v0.6.12"
disclaude --version
```

Stop any running service before upgrading and start it again afterwards with
`disclaude start`. The installation does not modify configuration or workspace
data. Existing 0.6.8–0.6.11 deployments keep their configuration and workspace
data; use the [installation/rollback guide](git-install.md) to switch releases.

For the Chromium container deployment, retain the profile volume when recreating
the container and do not use `docker compose down -v` if browser state must be
preserved. See [the Chromium container guide](../chromium-container.md) for the
volume and language settings.
