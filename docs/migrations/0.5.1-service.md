# 0.5.1：移除 Primary Node 的迁移说明

本页的旧名称仅用于迁移和历史对照，不是新的运行模式。#4924 移除主从/节点角色，保留渠道、会话、调度、HTTP API 和 harness 能力。

| 旧接口 | 0.5.1 |
| --- | --- |
| `disclaude-primary start` | `disclaude start`，旧 npm bin 不再提供 |
| `@disclaude/primary-node` / `packages/primary-node` | `@disclaude/service` / `packages/service` |
| `PrimaryNode` / `PrimaryAgentPool` | `DisclaudeService` / `ChatSessionPool` |
| `NodeType`、`NodeCapabilities`、`BaseNodeConfig`、`PrimaryNodeConfig` | 删除，无角色兼容别名 |
| `/list-nodes`、`/switch-node` | 删除；`/status` 查看服务状态，`/agent` 选择 harness/model 预设 |
| HTTP `/api/status` 的 `nodeId` | `instanceId`，仅用于诊断进程实例，不用于任务路由；`/api/ping` 不变 |
| `Dockerfile.primary`、Compose `primary` 服务 | `Dockerfile.service`、Compose `service` 服务 |
| launchd `com.disclaude.primary` | `com.disclaude.service` |

## 配置与数据

备份配置文件、workspace 和现有部署定义。渠道、agent/agents 预设、workspace、会话和定时任务的数据布局保持不变，不需要删除数据或重新建群。

删除旧的顶层 `primaryNode`、`primary`、`worker`、`nodeType`、`nodeId`、`nodeName`、`enableLocalExec` 角色设置；这些键不再被静默接受。删除 `--mode`、`--node-type`、`--node-id` 启动参数。渠道和 HTTP 监听地址仍由 channels 配置及 `--api-port` 等统一 CLI 参数控制。

服务构造函数仅接受可选的诊断 `instanceId`；旧构造参数中从未参与监听的 host/port/执行能力等选项已删除。HTTP 消费方如使用 `nodeId`，应显式更新为 `instanceId`。

## macOS launchd

1. 先备份旧 plist 和配置，记录原 Node/PATH、配置路径及日志目录。
2. 使用升级前的管理入口停止并卸载旧 `com.disclaude.primary` 服务，确认进程退出；将旧 plist 备份移出 `~/Library/LaunchAgents`。不要删除 workspace 或日志。
3. 升级安装后运行 `disclaude --version`、`disclaude start --help`，再按项目 launchd 指引生成/安装 `com.disclaude.service`。
4. 验证启动、健康检查、停止和重启；确保只有一个服务处理相同渠道。

新生成器发现旧 plist 时会拒绝继续，避免静默创建并行服务；它不会替用户停止服务或删除文件。回退时先停止新服务，再恢复备份的旧版本和 plist，不要同时启动两者。

## Docker Compose

使用升级前的 Compose 定义停止旧 `primary` 服务；保留命名卷，不执行 `down -v`。更新部署定义至 `Dockerfile.service` 和 `service` 后启动新服务，检查配置挂载、端口、卷、健康检查及依赖服务。若使用自定义容器名/监控标签，一并更新。回退同样先停新服务再恢复旧定义，保留数据卷。

## 发行验收

代码结构变化使旧的 Git 发行候选和指纹失效。必须重新生成远程候选，并重新执行 #4922 的 Linux/macOS、Node 20/22、npm 10/11 安装与服务生命周期测试。不能因旧 `disclaude-primary` 曾通过安装测试而保留该入口；新制品应仅导出 `disclaude`。
