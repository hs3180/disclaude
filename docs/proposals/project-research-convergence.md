# 项目与研究入口收敛

状态：待实现的设计提案及交付审查项，2026-09-16。关联 #4753、#4754、PR #5021。

用户指出 `/research` 与 `/project` 有较多重叠，要求对比并做取舍。目标是让用户在一个项目中管理工作空间、材料与多项研究，不需要维护两套同名项目；研究仍须提供独立于普通对话的持久交互体验。

## 当前实现及问题

| 维度 | `/project` | `/research` |
| --- | --- | --- |
| 入口 | 通用控制命令，`info/use/reset` | 飞书消息入口、索引与交互卡片 |
| 身份 | 会话绑定到工作目录，无独立持久项目 ID | 独立 UUID，持久研究状态 |
| 工作目录 | `ProjectManager` 为普通会话解析目录 | `workspace/.research-work/<id>`，不读取上述绑定 |
| 生命周期 | 切换目录时重置普通会话 | 计划、调查、综合、等待意见、暂停恢复、取消及归档 |
| 材料与成果 | 文件及项目状态摘要 | 材料、文档快照、意见处置、发现与来源、成果续研 |
| 访问范围 | 会话目录绑定 | 当前卡片操作限定创建用户及原会话 |

依据：`packages/core/src/control/commands/project.ts`、`packages/core/src/project/project-manager.ts` 和 `packages/service/src/research/{project,runner,feishu-controller}.ts`。

当前不是两份完全相同的实现，但用户面对两种“当前项目”，而目录、研究材料及身份没有明确关联。把研究入口改成 `/project research` 不会自动解决这些问题。旧的 Unified ProjectContext 提案还把 research 定义为模板，已不适用于本次交付。

## 建议取舍

1. 统一项目导航。项目承载工作目录及可访问的材料；一个项目可包含多项独立研究。研究索引应能说明归属并返回项目，而不是建立另一套通用项目管理入口。
2. 保留研究体验。范围、方向、证据、意见、阶段状态、文档协作、续研及恢复属于研究，不并入普通对话的 session reset，也不能由加载模板代替。
3. `/research` 可保留为研究快捷入口，与统一项目入口访问相同研究身份和状态。现有 `/project info/use/reset` 保持兼容；具体新增命令由导航设计确定，不先增加重复的 create/list/archive 命令集合。
4. 共享项目身份及目录关联，不强行合并存储模型。目录绑定与研究状态有不同生命周期；已有的研究 UUID、来源链接及卡片回调身份必须保留。
5. 研究启动时明确归属与执行目录，并持久保存。之后切换普通会话目录不应悄悄改变在途研究。项目材料目录与每项研究执行目录可分离，但必须能解释材料从哪里来、成果保存在哪里。
6. 项目级导航不得扩大访问权限。归属同一目录不意味着可以看到其他用户的研究或操作其卡片。飞书文档权限仍独立检查。

## 迁移与验收条件

- [ ] 从项目进入研究、从 `/research` 进入同一研究，以及从旧卡片重开，都指向相同身份和结果；不会复制研究记录。
- [ ] 同一项目能有两项独立研究；暂停、取消、归档其中一项不会改变另一项或普通会话。
- [ ] 在已绑定目录的会话创建研究时，界面明确展示归属、材料来源与执行目录；实际运行与展示一致。
- [ ] 研究执行期间使用 `/project use` 或 `reset`，在途研究保持原归属、目录及成果；新研究采用明确的新上下文。
- [ ] 目录不存在、移动或不可访问时，研究显式报错并保留状态，不静默使用另一个项目目录继续研究。
- [ ] 重启恢复后仍使用原归属、研究 ID、确认的阶段及材料；新意见按研究生命周期处理。
- [ ] 现有无项目关联的研究继续可访问，显示关联缺失而不根据当前会话目录自动猜测归属；绑定或迁移前展示目标，保留旧数据和回滚路径。
- [ ] 旧 `/project` 目录绑定、研究 JSON、卡片回调与成果续研链接经过兼容验证；不以重建研究替代迁移。
- [ ] 项目导航、快捷入口及旧卡片均遵守原用户/会话访问范围；跨用户和跨会话操作不能借统一入口绕过校验。
- [ ] 帮助、索引、卡片及设计文档使用一致概念，明确“项目”“工作目录”“研究”的关系，移除把 Research 当作模板/Skill 的当前使用说明。

这些条件需要实现和真实用户路径证据。既有研究生命周期测试、真实卡片验收和 CI 通过不能证明入口与项目模型已经收敛。
