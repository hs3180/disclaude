# 项目中的 Research Harness

状态：2026-09-17 按维护者最新要求修订交付设计；草稿 PR #5021 已改为 agent 决定工作更新的执行协议；专用命令和启用条件已移除；普通 agent 任务能力已接入；真实项目 UX 验收仍待完成。关联 #4753、#4754。

不提供独立 `/research` 命令，不设计 research 模式，也不要求用户启用研究开关。用户在现有项目中提出研究目标，由 agent 使用 harness 提供的能力持续开展工作。Agentic Research 仍需要持久、可观察、可介入、可重返的工作空间体验；取消专用命令和模式不等于退回普通聊天或仅加载一个 Skill。

## 产品与执行边界

项目提供统一入口、工作目录、材料和成果。研究是项目中的一种任务，一个项目可包含多项任务；任务具有独立执行身份及生命周期，但不另建一套“研究项目”来竞争项目身份。现有 `/project info/use/reset` 的目录控制契约应保留。自然语言提出研究需求后，目标、范围、材料、状态、证据和待处理事项在项目中持续可见，不要求用户先选择模式。

Harness 负责可复用的执行设施与状态契约，agent 决定如何调查和何时调整计划。方法论可作为按需使用的指导，但产品不得强制每项任务依次执行 `plan → investigate → synthesize`，也不得以固定三阶段 JSON 返回结构作为唯一的执行协议。执行预算、超时和安全停止仍由 harness 管理，耗尽时明确保留状态并报告原因，不能伪装成研究完成。

| Harness 能力 | 可观察的契约 |
| --- | --- |
| 项目上下文 | 工作目录、目标、材料、约束及成果持久化；绑定目录在运行中不随聊天切换而改变 |
| 资料获取 | 按可用工具和权限访问文件、文档或浏览器；来源不可读时明确记录缺口，不强制依赖某种浏览器或预装插件 |
| 证据与产物 | 保存来源、摘录或快照、发现、推断、不确定性及成果关联；来源结构合法不等于事实已验证 |
| 持续执行 | 跨 turn 推进，持久记录执行进展和检查点；运行状态与聊天历史分离 |
| 人工介入 | 补充材料、调整范围、提出反例、暂停或停止工作；反馈有接收和处理记录，可看见实际影响 |
| 恢复与并发 | 中断后核对最新材料及反馈，避免重复已确认操作；任务间状态、控制和结果隔离 |
| 成果延续 | 从成果或某项发现继续工作，保留来源、历史版本和关联，不悄悄改写终态结果 |

这些能力应能被其他长任务复用。暂不要求重写整个通用 Loop，也不要求一次抽象所有后端；优先复用当前 agent runtime、项目上下文和已有控制能力。具体工具协议与持久化适配需要在实现中明确，不能只把 Research 类改名为 Harness 就算完成。

## 实施增量：通用任务 turn 执行

`packages/service/src/harness/task-turn.ts` 已从研究 runner 中抽出工作目录校验、固定执行绑定、独立执行身份、时间预算、中断处理及 typed final result 读取。接口接受任务提示词并返回最终文本，不知道研究、阶段或 JSON schema；当前任务 runner 使用该接口，并提交通用工作检查点。它拒绝缺失目录，不创建替代 workspace。取消发生在执行前时不创建 agent，初始化期间取消则不启动 turn；中断或超时不返回晚到结果。`dispose()` 是取消请求，不能据此宣称子进程已退出。

该接口还不负责持久状态或跨 turn 调度，因此不是完整 harness。普通 agent 任务操作已接入同一服务状态与控制能力，真实 UX 验收仍待完成。普通构建故障诊断的真实模型 E2E（`tests/e2e/task-harness.test.ts`）直接通过此接口读取本地随机日志，不经过研究 controller/runner，14.5 秒通过；它仅证明普通任务的真实单 turn 复用，不满足下方非研究长任务及恢复验收。测试在正常完成后回收自己的临时目录，终止不确定时保留目录并报告。

## 实施增量：Agent 决定执行过程

实际 manager/runner 路径已删除 `plan/investigate/synthesize` 阶段选择和结果协议。`harness/task-checkpoint.ts` 定义通用的工作更新、证据、反馈回执及 `continue/waiting-user/complete` 执行状态。Agent 可以直接完成简单核验，也可以先收集证据、等待用户、再继续工作；这些状态不是研究方法或阶段。服务负责整体校验后提交状态：已有终态工作不可覆盖，工作更新不能删已有证据，反馈引用必须有效，待处理工作不能直接标记完成。12 个 turn 的预算耗尽时暂停，不能当作任务完成。

执行中新增反馈阻止使用旧结论结束任务；有效证据保留后，下一回合处理新反馈。用户停止工作时丢弃当时整个在途检查点，避免保存依赖已停止工作的结论。取消不接纳在途结果，暂停在当前回合收尾后生效。现有记录可直接读取，不移动 workspace、不改变 ID 或来源链接。

真实模型普通任务用例已验证：读取构建日志 → 等待用户选择输入 → 关闭并重开持久存储 → 接收选择 → 完成诊断，首次 50.3 秒、最终上下文实现复查 51.6 秒通过；未执行构建或改文件，测试目录回收。这是实际模型加持久状态/反馈的集成证据；存储重开不是进程崩溃验收，也没有真实飞书消息或点击。单次日志诊断另用 15.5 秒通过。真实价格核验在新协议下只执行一个模型 turn，24.3 秒得到 A=299/B=306/差额7；目录切换与重开后成果保留，测试目录回收。专用入口/开关已移除，普通 agent 任务操作已接入，但统一项目任务 UX 的真实验收尚未完成，不能据此宣称本版完整交付。

## 实施增量：默认项目任务入口

`/project` 默认展示工作目录和通用任务卡片，保留 `info/use/reset` 原控制路由。表单以自然语言填写目标、范围、材料，创建后先确认执行目录再开始；不要求选择 research 模式。独立 `/research` 产品路由已删除，未知 slash 文本沿用普通消息处理。普通对话 agent 也已接入同一任务能力，表单不是必需入口。

默认存储位于配置 workspace 的 `.disclaude/project-tasks/feishu/<app-namespace>`，namespace 为 app ID 的 SHA-256 前24位；访问任务时才创建存储，不因普通消息落盘。旧绝对路径环境变量继续指向原文件，仅作兼容覆盖；不会自动搬文件。旧卡片和来源 ID 保留。卡片文案以项目下的任务为单位，反馈、证据、控制及成果沿用同一执行能力。路由测试验证无专用配置创建、两个 app 隔离、同 app 重开及旧回调；真实卡片呈现与用户路径仍待验收。

## 实施增量：普通 agent 的任务能力

渠道在收到用户消息时签发短期上下文，并通过正常 MessageRouter/ChatAgent 提示词链路提供 `project_task` 能力。Agent 用共享 channel CLI 调用认证 REST API，可创建、分页列出（含归档）、查看任务或控制生命周期。没有关键词分流或新模式；任务仍由同一持久状态与执行器承载，后台执行不依赖普通回复继续占用一个 turn。

用户、会话和创建来源由服务绑定，操作 JSON 不接受这些身份字段或执行目录覆盖。创建时解析当前项目目录；旧 revision 的工具控制请求拒绝执行。上下文30分钟到期、渠道停止时撤销，服务重启后须由新用户消息获得新上下文；任务记录不因此丢失。重复创建使用当前消息和 requestId 关联原记录。正常消息在上下文容量不足时仍可处理，不因任务能力不可用丢弃对话。

实际 CLI 用例验证创建、幂等重试、查询、取消、归档、跨用户拒绝、身份覆盖拒绝、旧版本拒绝和撤销。配置模型的自然语言用例通过普通 agent 创建并启动任务，再由后台模型读取随机文件、返回正确标记与数量17，首次49.4秒、最终复查48.2秒通过；原文件内容未变，测试目录回收。全量回归4,841通过、6跳过，最新渠道/API相关测试236通过。卡片传输被捕获，不能替代真实飞书交互；实际进程中断后的恢复旅程也仍待验证。

## 实施增量：进程级存储恢复

`tests/e2e/project-task-process-recovery.test.ts` 使用真实独立 Node 进程和磁盘存储：首个检查点落盘后进入下一回合，竞争进程被存储锁拒绝；强制 SIGKILL 原进程并确认退出，新进程回收失效锁、呈现 interrupted，接收新反馈后继续。已提交的工作和证据保持原样，续跑仅执行一次并记录反馈应用。子进程有执行期限并在清理时确认退出，临时目录回收。执行器和卡片传输受控；此测试不证明真实模型后代进程终止，也不替代飞书/文档新反馈恢复旅程。

## 实施增量：真实模型取消后的工具进程回收

真实 Codex 测试先确认模型的 `sleep 30` 正在独立进程组执行，再取消任务。修复前，任务返回中断且 app-server 退出，但 sleep 被重新托管给 PID1 并继续运行；单独 agent 取消与立即清理 provider 两条路径均复现。修复在关闭 app-server 前采集仍可证明父子关系的独立进程组，发送 TERM/KILL 前重新核对组长 PID、组 ID、用户及启动时间；不扫描或终止无归属进程。独立组抗 TERM 和身份变化/其他组不受影响的回归通过。修复后的真实模型 E2E 11.2秒通过，在30秒自然结束前确认所有观察到的所属进程组消失，目录回收。

这证明本机当前 Codex 的正常取消路径。父进程先崩溃、子进程已脱离父子关系、组长先退出或清理期间新建进程等情形，仍不能仅凭该快照保证回收；其他 harness 与完整进程崩溃/文档新反馈旅程仍需验收。`runTaskTurn` 返回中断也不代表 OS 清理已同步完成。

## 实施增量：真实模型进程崩溃与新材料恢复

配置 Codex 的实际任务在执行 `sleep 30` 时，测试对拥有任务存储的独立 Node 进程发送 SIGKILL；2.5秒后观察到的 app-server 和工具进程组全部消失，没有手工回收。随后修改随机 inventory 文件，另一进程重开同一任务为 interrupted，接收“跳过已中断等待、读取新材料”的反馈并完成，结果包含新标记和数量9，反馈记录为已应用，源文件未被修改。可重复用例复查37.3秒通过，连同既有进程级存储恢复共2项通过。该用例现位于 `tests/e2e/project-task-process-recovery.test.ts`，通过 `DISCLAUDE_E2E_TASK_HARNESS=1` 启用；需先构建当前源码。任何需要测试脚本手工终止残留进程的情况都会使验收失败，保留必要诊断。

这里验证本机当前 Codex、一次服务进程 SIGKILL 与本地材料更新，卡片传输被捕获。首次检查点之前中断，不证明任意副作用可回滚；飞书文档新评论/正文、真实卡片重返、多提供方或整机故障仍需独立验收。

## 交付验收

- [ ] 用户在现有项目中用自然语言提出研究需求，无独立 `/research` 命令、research 模式或专用启用步骤。
- [ ] 项目入口可查看任务目标、状态、材料、证据、反馈和成果，离开后无需翻聊天记录即可重返。
- [ ] 简单核验与开放调查可采用不同推进方式，未被强制套入固定三阶段；实际工具调用及持久记录可验证行为。
- [ ] agent 能按需获取材料并记录可追溯证据；失败、冲突和未知可见，不虚构获取成功。
- [ ] 用户介入可改变后续工作，处理回执与实际证据/计划/成果变化一致；恢复前读取最新反馈。
- [ ] 暂停、取消、中断恢复和预算耗尽有明确的在途处理规则，保留成果且不重复已确认的操作。
- [ ] 同项目两项任务可独立控制；切换聊天目录不改变在途任务工作目录；跨用户/会话访问仍受原边界限制。
- [ ] 旧研究 JSON、目录、卡片回调和成果链接经过兼容验证；迁移可审阅、可回退，不静默搬文件或重建记录。
- [ ] 同一 harness 状态与控制能力至少通过一种非研究长任务验证，避免暗藏专用研究模式。
- [ ] 完成真实飞书用户路径验收，包括资料、介入、重返/恢复及成果追溯；测试后回收自有临时资源。
