# 项目中的 Research Harness

状态：2026-09-17 按维护者最新要求修订交付设计；草稿 PR #5021 的专用研究执行器尚不符合此边界，需要重构。关联 #4753、#4754。

不提供独立 `/research` 命令，不设计 research 模式，也不要求用户启用研究开关。用户在现有项目中提出研究目标，由 agent 使用 harness 提供的能力持续开展工作。Agentic Research 仍需要持久、可观察、可介入、可重返的工作空间体验；取消专用命令和模式不等于退回普通聊天或仅加载一个 Skill。

## 产品与执行边界

项目提供统一入口、工作目录、材料和成果。研究是项目中的一种任务，一个项目可包含多项任务；任务具有独立执行身份及生命周期，但不另建一套“研究项目”来竞争项目身份。现有 `/project info/use/reset` 的目录控制契约应保留。自然语言提出研究需求后，目标、范围、材料、状态、证据和待处理事项在项目中持续可见，不要求用户先选择模式。

Harness 负责可复用的执行设施与状态契约，agent 决定如何调查和何时调整计划。方法论可作为按需使用的指导，但产品不得强制每项任务依次执行 `plan → investigate → synthesize`，也不得以固定三阶段 JSON 返回结构作为唯一的执行协议。执行预算、超时和安全停止仍由 harness 管理，耗尽时明确保留状态并报告原因，不能伪装成研究完成。

| Harness 能力 | 可观察的契约 |
| --- | --- |
| 项目上下文 | 工作目录、目标、材料、约束及成果持久化；绑定目录在运行中不随聊天切换而改变 |
| 资料获取 | 按可用工具和权限访问文件、文档或浏览器；来源不可读时明确记录缺口，不强制依赖某种浏览器或预装插件 |
| 证据与产物 | 保存来源、摘录或快照、发现、推断、不确定性及成果关联；来源结构合法不等于事实已验证 |
| 持续执行 | 跨 turn 推进，持久记录执行进展和检查点；运行状态与聊天历史分离 |
| 人工介入 | 补充材料、调整范围、提出反例、暂停或停止工作；反馈有接收和处理记录，可看见实际影响 |
| 恢复与并发 | 中断后核对最新材料及反馈，避免重复已确认操作；任务间状态、控制和结果隔离 |
| 成果延续 | 从成果或某项发现继续工作，保留来源、历史版本和关联，不悄悄改写终态结果 |

这些能力应能被其他长任务复用。暂不要求重写整个通用 Loop，也不要求一次抽象所有后端；优先复用当前 agent runtime、项目上下文和已有控制能力。具体工具协议与持久化适配需要在实现中明确，不能只把 Research 类改名为 Harness 就算完成。

## PR #5021 现状与取舍

| 当前实现 | 处理决定 |
| --- | --- |
| `/research` 与 `/project` 首页别名 | 移除专用研究入口；不能改成 `/project research` 后继续保留相同模式设计 |
| `DISCLAUDE_RESEARCH_PROJECTS_DIR` 同时作为存储位置和启用开关 | 不再作为产品启用研究模式的条件；旧路径作为已有数据的兼容输入处理，迁移策略需显式定义 |
| `ResearchManager` 固定三阶段调度及 `runner.ts` 的专用阶段 schema | 拆分持久状态/控制能力与研究策略；改为 agent 在能力和预算范围内推进任务 |
| 研究 UUID 与独立目录 | 区分现有项目上下文和其下任务身份；保留已有记录标识，不创建重复项目来完成迁移 |
| 固定工作目录、证据/意见记录、暂停恢复、取消、幂等回调 | 作为 harness 和项目 UX 可复用能力保留，重新验证新执行路径 |
| 文档快照、显式导出、写入意图及只读核对 | 保留用户修改保护和不确定写入的处理契约，不绑定固定“综合阶段” |
| 历史卡片、成果链接及导航关联 | 通过兼容适配保留原用户/会话校验和可访问性；不得移动或删除历史 workspace 来掩盖身份变化 |

当前 `message-handler.ts` 仍按专用环境变量创建 `FeishuResearchController`，`manager.ts` 与 `runner.ts` 仍使用固定研究阶段。已实现的共享首页、目录绑定和历史关联是可复用的增量，**不是符合本设计的最终交付**。旧实现的真实飞书验证、模型 E2E 和 CI 只证明当时执行路径；不能直接转记为新 harness 的验收结果。

## 交付验收

- [ ] 用户在现有项目中用自然语言提出研究需求，无独立 `/research` 命令、research 模式或专用启用步骤。
- [ ] 项目入口可查看任务目标、状态、材料、证据、反馈和成果，离开后无需翻聊天记录即可重返。
- [ ] 简单核验与开放调查可采用不同推进方式，未被强制套入固定三阶段；实际工具调用及持久记录可验证行为。
- [ ] agent 能按需获取材料并记录可追溯证据；失败、冲突和未知可见，不虚构获取成功。
- [ ] 用户介入可改变后续工作，处理回执与实际证据/计划/成果变化一致；恢复前读取最新反馈。
- [ ] 暂停、取消、中断恢复和预算耗尽有明确的在途处理规则，保留成果且不重复已确认的操作。
- [ ] 同项目两项任务可独立控制；切换聊天目录不改变在途任务工作目录；跨用户/会话访问仍受原边界限制。
- [ ] 旧研究 JSON、目录、卡片回调和成果链接经过兼容验证；迁移可审阅、可回退，不静默搬文件或重建记录。
- [ ] 同一 harness 状态与控制能力至少通过一种非研究长任务验证，避免暗藏专用研究模式。
- [ ] 完成真实飞书用户路径验收，包括资料、介入、重返/恢复及成果追溯；测试后回收自有临时资源。
