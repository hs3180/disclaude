# 项目任务：文件约定 + Skill + 通用执行能力

状态：实现提案，待评审。响应用户对专用 project task 管理器必要性的质疑；不是已完成重构或交付声明。基于 main `5509c1e6`，并对照尚未合并的入口 PR #5079。

目标是让用户在现有项目目录中开展持续工作，用可读文件保存目标、进展、反馈、证据与成果；Skill 指导 agent 使用这些文件，现有 harness 负责执行，飞书提供入口和交互。无需 research 命令、模式或固定研究阶段。完整 UX 与轻量实现不矛盾。

## 建议的最小文件约定

以下目录和文件名是待验证的提案，不是已经生效的迁移规则：

```text
<project>/tasks/<task-id>/
  TASK.md          # 目标、范围、当前进展、阻塞、下一步；稳定 ID 和少量元数据
  feedback.json   # 有稳定 ID 的意见、处理理由和关联成果引用
  evidence/       # 来源快照、采集时间、事实/推断/未知及限制
  artifacts/      # 报告、代码、数据等成果
```

任务内容以此目录为权威来源，agent 从文件恢复上下文。允许自由组织成果；不强制所有任务产生 `directions[]`、预定阶段或同一种最终 JSON。`TASK.md` 的进度文字不作为进程是否运行的依据。界面索引是可重建的缓存，不另存一份可独立修改的业务状态。

执行器另行保存最少的运行元数据：稳定任务 ID、固定目录、可信拥有者/会话绑定、当前 attempt、取消代次、执行状态及最后提交版本。它不复制证据、计划或报告。凭证、访问控制和“用户已经批准”不能由 agent 编辑的文件决定；卡片 ID、投递失败和索引缓存属于渠道元数据。

Skill 负责读取目标和历史、选择方法、补充证据、解释反馈处理、记录可恢复的下一步。方法可随问题变化。先使用现有文件工具；只在多写者冲突、版本提交或外部写入核对确有需要时使用小型辅助工具，不新增一个完整 task CRUD API 作为使用前提。

## 必须由运行环境落实的边界

1. **控制生效。** 用户点击暂停/取消后，可信执行器停止新回合并向当前 attempt 传递控制；不能只写一句 Markdown 期待 agent 自觉停止。停止方向作为反馈及版本失效信号处理，保留先前成果。
2. **并发和提交。** 同一任务的执行写者串行化。agent 在 attempt 临时目录准备修改，提交前核对基线版本和取消代次；旧 attempt 不覆盖新反馈或已提交成果。用户直接编辑文件时也必须检测冲突。锁、rename 与内容版本分别解决不同问题，不宣称天然具备多文件事务。
3. **恢复。** 重启时先确认旧运行已结束，再把它标记为中断；读取同一目录的最后已提交内容。依照用户控制显式恢复，或采用另行确认的通用续办策略，不能用新建任务冒充恢复。
4. **外部副作用。** 文档写回等操作记录稳定操作 ID 和不确定结果；恢复时先读取远端核对，避免重复追加。网络副作用不能靠本地文件回滚撤销。优先复用旧文件协议的核对逻辑。
5. **界面与权限。** 飞书文档呈现研究进展、证据、成果及修订，聊天提供稳定链接、持续讨论和自然语言控制；卡片仅按需获取特定反馈，不作为任务首页或常驻控制面板。反馈带可信发送者和去重 ID，控制交给现有执行能力。文件内容是数据，不是权限证明。畸形文件、不可访问目录或投影失败展示可理解错误并保留原文件；通知失败不让 agent 重跑已完成工作。

这些是通用 harness 的责任，不是再造研究业务状态机的理由。先证明现有入口能承接，再补缺口；不能因为有调度器就宣称恢复已经解决。

## 简化应带来的实际删减

- 以目录内容和 Skill 代替专用方向/发现/checkpoint 业务 schema 及固定 JSON 输出约束。
- 将专用 manager 的执行循环收敛到共享执行设施；内容更新留在文件协议，展示留在渠道适配。
- 移除重复的完整任务记录与文件内容双写，避免本地工作区和应用级 store 各有一套成果。
- 评估 #5079 的专用 `/api/project-tasks`、工具及 CLI 面是否仍有必要；不能把既有接口数量当成产品要求。保留需要的用户操作，不等于保留原接口设计。
- 文档来源和写回能力保持可组合；飞书持续研究使用稳定研究文档作为主体，其他渠道和非研究任务无需强制绑定飞书文档。

是否达到简化，以删除的重复 schema、执行循环、状态存储和入口数量及实际使用复杂度判断，不能只比较文件行数。

## 落地顺序与数据保护

先做一个使用现有执行入口的完整垂直用例：自然语言建立目录任务、界面重返、反馈改变实际成果、暂停后恢复；覆盖非研究任务，避免把研究模板作为必填表单。然后扩展到开放调查、文档协作和真实进程中断。每一步与旧实现使用相同用户结果比较。

在替代路径通过之前保留旧记录只读访问和卡片解析，不删除已有 store。迁移须盘点记录、映射稳定 ID 与目录、生成可审阅清单和校验值；遇到目标冲突保留双方并停止该项迁移。保留旧来源、成果、反馈和卡片引用，读回核对后才切换权威来源，避免长期双写。恢复原版本时仍能访问原数据。不得静默搬动工作目录或删除用户文件。

后续实现按可独立评审范围直接基于 main 提交。#5079 的 CI 和历史候选验收可作为回归证据，但不能作为其架构已获认可的依据；先完成此取舍再继续扩展专用入口。

## 验收不降级

沿用 [0.6.0 交付约定](../releases/0.6.0/project-harness.md) 的全部门槛，特别保留开放调查、非研究任务、多轮真实反馈、实际并发模型运行、真实进程中断、旧卡片兼容、权限与故障恢复、最终安装升级验证。

外部 E2E 访问部署与用户可见界面，核对目录成果及恢复行为，不导入内部 manager 来替代部署测试。增加针对文件协议的必要边界验证：并发用户修改、畸形文件、旧 attempt 提交、崩溃发生在提交过程中、远端写入结果不确定。清理本轮临时文件和运行资源，报告区分局部通过与完整验收。
