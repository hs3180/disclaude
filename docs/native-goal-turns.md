# Native Goal turn execution port

`NativeGoalExecutor.runTurn(goal, source, signal)` adapts an explicitly authorized active Goal round to `AgentTaskRunner`. Its result is structurally compatible with the settled-turn report expected by `GoalController`. The host supplies current authorization, runtime selection and actual channel callbacks; source strings alone are not authentication. The active Goal must match the captured chat and Project. The task runner pins the existing directory and owns an independent native identity.

A query-local `goal_report` tool captures progress, artifact references and acceptance checks for the exact revision. Its receipt says `accepted: true, saved: false`: this is a proposal, not a persisted Goal transition. Completion proposals must cover every criterion with recorded evidence. Model arguments cannot select another Goal/revision/source. A worker ends after its round, so asynchronous questions that would need to resume a later round are disabled. Blocking questions can remain within the owned live query; a blocked report is handled by the controller’s explicit resume flow. The host stores the report only after the native task, background continuation and callbacks settle successfully. Artifact references are assertions for the host/reviewer to evaluate; this tool does not verify file contents.

A failed/truncated native result, failed delivery or absent assessment does not become completion and is not automatically retried. Cancellation closes the collector and stops the owned task; executor shutdown waits for owned task settlement. `isBusy(chatId)` remains true until this cleanup finishes. The existing per-input data limits still apply; no Goal step, token or duration budget is introduced.

This port does not register chat commands, activate Goals, perform policy checks or restore active Goals after restart. One owning controller must enforce revision/admission ownership. `GoalExecutionService` provides the service binding, current policy/Project checks, captured runtime and final notifications; the CLI injects it only into the Feishu user control handler and drains it before stopping channels.

Regression tests run the actual task runner, factory and ChatAgent against local SDK ports. They cover success, missing assessment, failure after a local write, delayed/failed callback delivery, background continuation, cancellation, close and invalid Project/source. They do not establish live model/platform acceptance.
