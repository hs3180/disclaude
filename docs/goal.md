# Goal 目标记录

飞书聊天支持用 `/goal` 直接启动当前聊天、当前 Project 的目标。普通聊天中提及目标不会自动创建 Goal。话题内回复保留在原话题，记录在同一聊天和 Project 内共享。

```text
/goal 完成季度研究报告 | 每项结论引用原始证据 | 列出尚未验证的条件
```

`/goal <目标> | <验收…>` 一步完成保存和启动：只写一段文本时以该文本同时作为目标与验收要求。启动需要宿主提供原生执行能力，并保留真实来源消息、用户和话题上下文；当前默认配置尚未接入执行器，未启用时明确拒绝启动且不落盘。停止直接使用 `/stop`，无需记住目标 ID 或版本。

`|` 分隔目标和各项验收要求。切换 Project 后仅针对当前绑定目录启动，其他聊天不能读取或修改记录。记录随服务重启保留；目标 Project 暂不可用时绑定不会自动切回其他目录，`/goal <prompt>` 启动会被拒绝直到目录恢复。

执行能力必须在实际调度时重新检查权限与 Project，来源字段本身不代表授权。回执不会把“已记录停止”说成“所有工作已退出”；`/stop` 先发送终止信号，原生取消结算单独等待。执行能力只注入飞书用户控制入口，模型可调用的 REST control 入口不获得这项能力。当前命令不设置步数、时长或 token 预算。原生调度、验收工具及服务生命周期接线仍需完成。
