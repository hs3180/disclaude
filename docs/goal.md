# Goal 目标记录

飞书聊天支持用 `/goal` 明确保存、查看和修订当前聊天、当前 Project 的目标。普通聊天中提及目标不会自动创建 Goal。话题内回复保留在原话题，记录在同一聊天和 Project 内共享。

```text
/goal create 完成季度研究报告 | 每项结论引用原始证据 | 列出尚未验证的条件
/goal list
/goal show <返回的 ID>
/goal edit <ID> <当前版本> 完成修订后的报告 | 纳入最新反馈 | 保存实际验收结果
/goal start <ID> <当前版本>
/goal pause <ID> <当前版本>
/goal resume <ID> <当前版本>
/goal stop <ID> <当前版本>
```

`|` 分隔目标和各项验收要求。`show` 返回当前版本；修订需带上该版本，遇到并发更新会拒绝覆盖并提示重新查看。列表每页 20 项，可用 `/goal list 2` 查看下一页。切换 Project 后仅展示当前绑定下的记录，其他聊天不能读取或修改。

创建时保存的是**尚未启动的草稿**。明确 `start` 后，默认服务使用当前聊天/话题所选模型，按最新要求持续推进并保存每轮进展、产物和验收记录；不会因一轮结束而自动退出 Goal。完成或需要用户决定时，向原聊天/话题发送状态回执。模型与连接配置在启动或恢复时固定，普通聊天切换模型不会改变已有 Goal。

执行需要原生回合成功结算，验收报告才会保存。报告完成必须覆盖全部验收要求并引用已记录产物；这仍是 agent 的验收判断，不能替代用户要求的外部 review 或真实平台验收。原生失败、缺少报告及未知结果不会自动重试，也不会把已有操作重新执行。

修改要求前建议先暂停并等待当前工作结算，再编辑、恢复。旧回合结果不能覆盖新要求；执行中收到修改而导致旧验收失效时，会停止推进并提示核对已有操作。每轮调度及结果保存都会重新检查权限和当前 Project。

绑定的项目目录缺失时拒绝启动和恢复，但仍可查看、暂停或停止。暂停和停止先确认已持久保存的决定；原生查询和已发出的通道请求结算前，拒绝恢复。执行或最终回执尚在处理时，不能切换该聊天的 Project。`/stop` 管理普通聊天会话；Goal 使用自己的 `/goal pause`、`/goal stop`。

服务关闭会取消并等待所属工作。Goal 记录随重启保留，服务不会自动重放旧执行；`show` 会指出 active 记录当前没有所属执行，核对旧操作后再明确暂停、恢复。执行能力只注入飞书用户控制入口，模型可调用的 REST control 入口不获得这项能力。宿主未配置执行器时会明确拒绝启动。没有 Goal 步数、时长或 token 预算。
