# 0.5.2 security boundary review

Reviewed 2026-09-11 against main `2f625607` and the P0 branches linked below. This is a source/fixture review, not a penetration-test or release certification. Pending PRs and unavailable external checks remain pending.

## Responsibility

The agent/harness owns sensitivity declarations, service-specific credential policy, endpoint selection and task authorization. disclaude provides tools for private handoff, secure credential persistence, explicit output protection and owned-process cleanup. It enforces concrete transport/process boundaries; it does not infer that a field name, token shape or arbitrary user text is sensitive.

Private actions are installed by the integration. A submitted card selects neither a new consumer nor new command arguments. The consumer owns any exchange, target, issuer expiry and derived-credential distribution. Original form values are not persisted or exposed through an agent-readable retrieval API.

## Dependency evidence

`npm audit --omit=dev --json` against the current lockfile returned 26 package findings (3 critical, 13 high, 8 moderate, 2 low). The response includes packages marked `dev: true` in the lockfile, including Vitest; these counts are recorded as returned and are not production-only exposure counts. Raw audit data is kept locally at `/tmp/052-security-audit.json`; it contains advisory metadata, not application credentials.

- Lockfile `protobufjs` 7.5.4 is affected by the schema code-generation advisory. The installed Feishu SDK uses `protobufjs/minimal` and generated trusted schemas (`lib/index.js` around its `$protobuf` import), not attacker-provided schema loading. This source review therefore does not establish that code-generation exploit path in disclaude. Other decoder/DoS advisories and patch upgrades still need dependency maintenance. See the [upstream protobuf advisory](https://github.com/protobufjs/protobuf.js/security/advisories/GHSA-xq3m-2v4x-88gg).
- Vitest 3.2.4 is a development dependency. The critical advisory requires a listening Vitest UI server; CI uses `vitest --run`. Upgrade the test toolchain separately and do not expose its UI. See the [upstream Vitest advisory](https://github.com/vitest-dev/vitest/security/advisories/GHSA-5xrq-8626-4rwp).
- Axios 1.13.6 is transitively constrained by Feishu SDK 1.59.0 (`~1.13.3`). Plan an SDK/HTTP dependency update with callback and transport regressions, rather than forcing an untested transitive major override. The audit also reports ws, qs and other dependencies; none are declared fixed by this review.

## Integration obligations

Declare a value before it can reach a protected sink and retain the declaration until asynchronous diagnostics drain. Use `SensitiveOutputFilter` with a `StringDecoder` for byte streams. Keep the result of a private consumer non-sensitive; close/await its work before returning, because protection cannot cover detached work after its declaration is released. Never return the original value through a tool result or store it in `.runtime-env`.

Each installed private action must document its consumer, authorization decision, expiry and revocation. The core form binding expires after five minutes and is one-use; it does not choose provider credential lifetimes. No built-in real authentication consumer or external Feishu delivery acceptance is claimed by this document.
