# 研究文档协作

把研究文档作为共同工作的界面：呈现目标、计划、发现和待讨论问题，让用户直接编辑或评论；在下一阶段开始及恢复执行前同步最新反馈，写明处理结果，再调整研究。研究方法和资料工具随任务选择，无浏览器、多 Agent 或交互卡片前置依赖。

开始时创建或关联用户授权的研究文档。使用已安装的飞书文档工具（本仓库提供 `lark-docs`），先查实际 CLI help 确认正文与分页评论读取能力。不能用研究启动请求推断额外分享权限。已有文档保留用户内容；新文档可采用 [研究模板](assets/research.md)。

修订当前结论时，先完整读回正文并保留被替换段落的原文，再用一次 targeted 文档写入同时保留历史段落。重新读回后逐字核对旧段仍在、当前结论和来源完整；发现缺失时只从可核对的旧读回恢复，不能凭记忆补写。核对历史时直接比较保存的完整正文读回，区分状态元信息和需要保留的结论，不依赖单独的历史审计脚本。

用户应能从飞书文档查看支撑结论的产物。关键实验的脚本、运行条件和观察结果直接放入文档；较大产物使用已有附件能力提供用户可访问的链接。不要只给本地路径或仅在项目目录存在的 Markdown 链接。

用任务独有的本地目录保存必要的原始读回和产物。读取 [反馈与恢复协议](references/protocol.md)，以飞书文档正文和评论作为协作状态；不创建额外任务状态机或文件索引。脚本不调用飞书、不启动调度、不创建群聊；工具调用由执行 agent 完成，群聊/会话编排由 #4754 承接。

每轮协作：

1. 获取完整正文和全部评论（包括新增回复），保留原始响应；分页不完整时保留上一次成功读回并说明未同步。
2. 结合正文上下文解释用户意图；对待澄清意见在文档中明确提问，不自行把等待算作回答。
3. 以增量方式写入研究计划、证据或结论，重新完整读取并核对用户内容、来源和评论均保留。写入结果不明确时先读回再决定是否重试。
4. 未解决反馈在文档或本地工作记录中明确保留；不能宣称已全部处理。完成前再次完整读回，取消只停止后续执行并保留文档与产物。

仅本地检查点通过不能宣称真实飞书协作通过。交付时分别记录代码/fixture 测试和真实用户文档反馈的证据。
