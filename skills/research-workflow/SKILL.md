# 研究文档协作

把研究文档作为共同工作的界面：呈现目标、计划、发现和待讨论问题，让用户直接编辑或评论；在下一阶段开始及恢复执行前同步最新反馈，写明处理结果，再调整研究。研究方法和资料工具随任务选择，无浏览器、多 Agent 或交互卡片前置依赖。

开始时创建或关联用户授权的研究文档。使用已安装的飞书文档工具（本仓库提供 `lark-docs`），先查实际 CLI help 确认正文与分页评论读取能力。不能用研究启动请求推断额外分享权限。已有文档保留用户内容；新文档可采用 [研究模板](assets/research.md)。

用任务独有的本地目录保存检查点和产物。读取 [反馈与恢复协议](references/protocol.md)，使用 `scripts/state.mjs` 管理任务/文档绑定、反馈和写回状态。脚本不调用飞书、不启动调度、不创建群聊；工具调用由执行 agent 完成，群聊/会话编排由 #4754 承接。

每轮协作：

1. 获取完整正文和全部评论（包括新增回复），保留原始响应；规范化为协议中的 snapshot。读取失败或分页不完整时保留旧检查点，说明未同步，暂停依赖这些反馈的阶段。
2. `sync` 识别正文变化和新增/编辑评论；结合正文上下文解释用户意图。对待澄清的意见在文档中明确提问，不自行把等待算作回答。
3. 通过 `prepare` 记录拟采纳、待澄清或未采纳意见及理由。检查最新正文仍与准备版本一致，然后把返回的 fragment 追加到文档；不整篇替换。把研究计划/结论的实质改动另作增量更新，并在下一次 sync 核对。
4. 重新完整读取文档，`ack` 确认写回后才把反馈标为已处理；并发编辑、未知写入或重启后的恢复按协议执行。反馈状态是处理记录，不能替代真正补充证据或修改研究结论。
5. 未解决反馈处理后推进研究阶段；完成前再次同步，保留结论、来源、分歧和反馈记录。取消只停止后续执行，保留文档与产物。

仅本地检查点通过不能宣称真实飞书协作通过。交付时分别记录代码/fixture 测试和真实用户文档反馈的证据。
